# 真实人生场景入口与人生沙盘模拟：系统结构图

> 用途：把“现实场景入口”如何接到现有 `book-kb-multi` 系统里画清楚。

## 1. 总图

```text
真实人生场景
（升学 / 求职 / 关系 / 育儿 / 家庭 / 转型）
        ↓
场景入口
（场景卡、年龄段、问题描述、真实原话）
        ↓
全景地图
（选项、路径、风险、资源、兴趣、能力）
        ↓
Problem Case
（把场景转成可分析的问题对象）
        ↓
思想伙伴选配器
（多视角解释 / 角色镜头 / 思维伙伴）
        ↓
学习路径地图
（书、概念、练习、输出、复盘）
        ↓
能力路径
（选择能力、判断能力、关系能力、表达能力）
        ↓
选题中台
（真实场景 -> 情绪/需要 -> 选题/标题/内容）
        ↓
行动与复盘
（最小行动、记录反馈、再次进入系统）
```

## 2. 这个系统里每层负责什么

### 2.1 场景入口

负责接住用户真正会说的话：

- “我不知道该选哪所学校。”
- “我不知道自己适合什么专业。”
- “我想换工作，但不知道下一步怎么走。”
- “我在关系里总是重复同样的模式。”

它的任务是把“现实处境”变成一个可以进入系统的门。

### 2.2 全景地图

负责让用户先看见世界有什么，而不是马上给结论。

典型输出：

- 选择维度
- 路径分叉
- 风险提示
- 资源边界
- 兴趣与能力的匹配

### 2.3 Problem Case

负责把场景结构化，形成可以分析、可以推荐、可以复盘的核心对象。

它接着：

- 原话
- 场景
- 情绪
- 需要
- A / B / C
- 最小行动

### 2.4 思想伙伴选配器

负责从不同学派、不同作者、不同角色角度看同一个问题。

它回答的是：

- 这件事还能怎么理解？
- 哪个视角最适合当前场景？
- 哪种说法更能帮用户看见盲区？

### 2.5 学习路径地图

负责把理解转成可练习、可推进的路径。

它回答的是：

- 我该学什么？
- 我该练什么？
- 我下一步要做什么？

### 2.6 能力路径

负责把这个系统从“理解问题”推进到“发展能力”。

它强调的不是单次答案，而是：

- 如何形成判断力
- 如何形成选择力
- 如何形成关系能力
- 如何形成表达与行动能力

### 2.7 选题中台

负责把真实场景反向转成内容表达。

它回答的是：

- 这个场景为什么会引发共鸣？
- 它真正对应的需要是什么？
- 怎么写成一篇内容？
- 怎么做成一张图？

### 2.8 行动与复盘

负责把系统闭环起来。

如果没有这层，系统就会停在“看懂了”。

有了这层，系统才能变成：

- 看见
- 试一下
- 记录
- 复盘
- 再进入

## 3. 和已有模块的关系

| 现有模块 | 在新结构中的角色 |
| --- | --- |
| 书库首页 | 书与知识资产的入口层 |
| Problem Case | 场景对象的分析中枢 |
| 思想伙伴选配器 | 多视角解释层 |
| 学习路径地图 | 理解到练习的过渡层 |
| 能力路径 | 人生阶段能力发展层 |
| 选题中台 | 现实场景到内容表达的翻译层 |
| 社会事件入口 | 外部现实采样层 |
| 3D 书库 | 空间化浏览入口层 |

## 4. 这张结构图的判断

它说明：

**真实场景入口不是一个新的孤立功能，而是把现有所有模块重新串起来的上游入口。**

换句话说：

- 书库负责“有什么”；
- 场景入口负责“我现在在哪”；
- Problem Case 负责“我卡在哪里”；
- 思想伙伴负责“还能怎么看”；
- 学习路径负责“接下来怎么练”；
- 能力路径负责“我怎样成长”；
- 选题中台负责“怎么表达出去”。

这就是整套系统的骨架。

## 5. 对象流结构

这套系统至少需要 5 个核心对象，而不是只靠一段用户输入。

```text
LifeScene
真实人生场景：用户现在处在哪类处境里
        ↓
SceneMap
全景地图：这个处境里有哪些维度、路径、风险和资源
        ↓
ProblemCase
问题对象：用户真正卡住的问题是什么
        ↓
GuidanceBundle
引导包：思想伙伴、学习路径、能力路径、书/卡片证据
        ↓
ActionReview
行动复盘：最小行动、反馈、下一次进入点
```

### 5.1 LifeScene

负责回答：

- 用户从哪个真实处境进来；
- 他通常会怎么描述这个处境；
- 这个场景和哪些问题卡有关；
- 这个场景可以通向哪些学习路径和能力轴。

### 5.2 SceneMap

负责回答：

- 这个场景的关键选择维度是什么；
- 有哪些可比较路径；
- 哪些信息还缺；
- 哪些风险容易被忽略；
- 用户应该先看全景还是先补输入。

### 5.3 ProblemCase

负责把用户原话收敛成可分析对象。

```text
原话
-> 场景
-> 触发 / 选择 / 不确定性
-> 情绪和需要
-> 当前问题命名
-> 可进入的路径
```

### 5.4 GuidanceBundle

负责把系统已有资产打包给用户，而不是让用户自己在书库里找。

包含：

- 思想伙伴视角；
- 学习路径；
- 能力路径；
- 相关书和卡片；
- 最小练习；
- 内容转译切口。

### 5.5 ActionReview

负责闭环。

如果没有这一层，系统只是“解释器”；有了这一层，系统才会变成“成长导航器”。

## 6. 模块接口图

```text
用户真实原话
        ↓
[LifeScene Router]
        ├─ 匹配场景：升学 / 求职 / 关系 / 育儿 / 家庭 / 转型
        ├─ 识别阶段：学生 / 家长 / 职场 / 关系 / 自我发展
        └─ 生成初始场景卡
        ↓
[SceneMap Builder]
        ├─ 选择维度
        ├─ 路径分叉
        ├─ 风险提示
        ├─ 信息缺口
        └─ 推荐比较项
        ↓
[Problem Case Adapter]
        ├─ 原话重述
        ├─ 问题命名
        ├─ 情绪 / 需要
        ├─ 当前卡点
        └─ 最小行动候选
        ↓
[Existing Product Modules]
        ├─ 思想伙伴选配器
        ├─ 学习路径地图
        ├─ 能力路径
        ├─ 书 / K / N 卡
        └─ 选题中台
        ↓
[Review Loop]
        ├─ 记录行动
        ├─ 回收反馈
        ├─ 更新问题卡
        └─ 再次进入场景
```

## 7. 第一版页面层级

| 层级 | 页面 / 区块 | 作用 |
| --- | --- | --- |
| L1 | 场景入口列表 | 展示用户能从哪些真实处境进入 |
| L2 | 单场景首页 | 展示场景说明、原话输入、全景地图 |
| L3 | 场景地图区 | 展示维度、路径、风险、资源 |
| L4 | 问题转译区 | 把场景转成 Problem Case |
| L5 | 继续探索区 | 接思想伙伴、学习路径、能力路径 |
| L6 | 最小行动区 | 给出今天能做的一步 |
| L7 | 复盘入口 | 让用户带着反馈再次进入 |

第一版可以先用静态 Markdown / 配置驱动，不要求每个区块都已经变成正式功能。

## 8. 与 2.5D / 3D 页面的边界

当前结构图只定义“场景系统骨架”，不定义空间视觉实现。

| 项目 | 本文档负责 | 2.5D / 3D 页面负责 |
| --- | --- | --- |
| 数据对象 | `LifeScene`、`SceneMap`、`SimulationStep` | 可读取这些对象做空间呈现 |
| 用户任务 | 从真实场景进入问题和行动 | 用空间方式浏览书、主题或场景 |
| 交互逻辑 | 选择维度、问题转译、最小行动 | 拖拽、缩放、点位、镜头移动 |
| 验证重点 | 是否能承接真实处境 | 是否能提升探索感和可理解性 |
| 当前动作 | 写清产品和数据结构 | 不在本任务内改动 |

协作原则：

- 场景系统先把“东西是什么”定义清楚；
- 2.5D / 3D 再决定“这些东西怎么被看见”；
- 两边可以通过稳定对象对接，但当前不要互相改文件；
- 如果未来要合流，优先通过配置数据合流，而不是把产品逻辑写进 3D 组件。

## 9. 数据闭环

```text
用户选择场景
-> 生成场景卡
-> 生成问题卡
-> 用户进入学习 / 能力 / 思想伙伴路径
-> 用户执行最小行动
-> 用户记录反馈
-> 系统更新：
   - 哪个场景最常被选择
   - 哪类问题最常出现
   - 哪条路径最有继续探索意愿
   - 哪个最小行动最容易完成
```

闭环后的数据不只是产品指标，也会反向喂给选题中台：

- 高频场景可以变成系列选题；
- 高频原话可以变成标题素材；
- 高频情绪可以变成内容切口；
- 高频能力缺口可以变成学习路径或课程雏形。

## 10. 第一版落地判断

如果只做一个“场景分类页”，这件事不成立；如果一上来做完整人生沙盘，又会过大。

最合适的第一版是：

```text
3 个真实场景样张
+ 1 套统一场景对象
+ 1 套场景到 Problem Case 的映射
+ 1 套最小沙盘推演模板
+ 1 个复盘口径
```

这能让系统先证明：

- 用户能从真实处境进入；
- 系统能把处境转成问题；
- 问题能继续接现有资产；
- 输出不会停在宏大解释，而能落到行动。
