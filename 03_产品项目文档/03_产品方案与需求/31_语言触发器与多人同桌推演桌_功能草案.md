# 功能草案：语言触发器 + 多人同桌推演桌

> 状态：v0.1 草案
> 目标：把“语言、视角、模式、情绪、需求”统一母题，变成可交互的产品能力。
> 关联：`Problem Case`、`ThoughtPartnerTool`、`LearningPathMap`、`ContentOpsCenter`

## 1. 功能目标

让用户不只是“看推荐”，而是能把一段原话、一个冲突、一个问题放进系统里，看到：

- 这句话触发了什么模式
- 背后可能是什么视角
- 情绪对应了什么需要
- 不同角色会怎么理解这件事
- 下一步最小行动是什么

## 2. 功能 A：语言触发器

### 2.1 输入

- 一句原话
- 一段对话
- 一个标题
- 一条评论
- 一个让人卡住的场景描述

### 2.2 系统要做的事

1. 识别原话中的关键触发词。
2. 判断它可能激活的解释框架。
3. 标记它背后的情绪倾向。
4. 推测它可能关联的需要。
5. 给出可点击的下一步：问题卡、思想伙伴、学习路径、选题角度。

### 2.3 输出

- 原话重述
- 触发词高亮
- 可能视角
- 可能模式
- 可能情绪
- 可能需要
- 推荐继续探索入口

## 3. 功能 B：多人同桌推演桌

### 3.1 核心想法

用户不只是看系统“推荐了谁”，而是让几个角色真的围绕同一个问题开始推演。

这张桌子里，用户自己也在场。

### 3.2 角色类型

可按三层配置：

#### 第一层：位置
- 老板
- 下属
- 伴侣
- 朋友
- 甲方
- 旁观者
- 当事人

#### 第二层：风格
- 结构型
- 共情型
- 质疑型
- 发散型
- 行动型
- 安抚型

#### 第三层：人格标签
- 可以支持 MBTI 或类似标签
- 但只作为表层沟通风格，不作为底层判断

### 3.3 一桌怎么跑

```text
输入一个问题
-> 选择 3-5 个角色
-> 用户加入推演
-> 每个角色先说“我怎么看”
-> 再说“我担心什么”
-> 再说“我会怎么推进”
-> 系统收敛出分歧点、共识点和最小行动
```

### 3.4 输出

- 角色立场卡
- 分歧点
- 共识点
- 盲区提示
- 下一步行动
- 可保存分享的推演卡

## 4. 和现有产品的接法

### 4.1 接 Problem Case

Problem Case 负责提供：

- 原话
- 场景
- 情绪
- 需要
- A / B / C 拆解

语言触发器是 Problem Case 的升级分析层。

### 4.2 接思想伙伴选配器

思想伙伴选配器负责给“谁来参与推演”做功能位分配：

- 主镜头
- 翻译者
- 校正者
- 行动伙伴
- 表达伙伴

多人同桌推演桌则把这些功能位具象化成“桌上角色”。

### 4.3 接学习路径地图

推演桌最后要落到：

- 该学什么
- 该练什么
- 该输出什么
- 该回到哪条路径继续

### 4.4 接选题中台

如果用户的问题最终要做成内容：

- 情绪是什么
- 需求是什么
- 视角冲突是什么
- 适合什么切口
- 标题和结构怎么写

## 5. 第一批适合做的样张

### 样张 1：说话一秒被触发

输入：
- “你怎么又这样？”
- “我只是提醒你。”

输出：
- 语言触发器识别
- 防御模式
- 可能需要：被尊重、被理解、边界
- 多角色推演：伴侣 / 朋友 / 旁观者 / 安抚者

### 样张 2：会议里没人说真话

输出：
- 权力距离
- 安全感不足
- 共享意义池不安全
- 角色推演：主持人 / 下属 / 管理者 / 关系顾问

### 样张 3：同一句话，不同人听出不同意思

输出：
- 视角差异
- 世界模型差异
- 解释框架差异
- 角色推演：结构型 / 共情型 / 质疑型 / 行动型

## 6. 风险与边界

- 不把 MBTI 当真理。
- 不把角色推演做成纯聊天。
- 不替代专业心理支持。
- 不把分析做得太玄，必须回到原话和场景。
- 不让用户只看到“角色扮演”，要看到“解释差异”和“需求差异”。

## 7. 价值判断

这个功能的价值不在于“更会聊天”，而在于：

- 把语言当入口。
- 把视角差异变成可见结构。
- 把模式触发变成可解释对象。
- 把情绪变成需求线索。
- 把多人推演变成真实问题的共同思考空间。

它会让产品更像一个“可参与的思想现场”，而不只是一个推荐器。
