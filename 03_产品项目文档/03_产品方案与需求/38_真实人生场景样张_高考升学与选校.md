# 场景样张：高考升学与选校

> 状态：v0.2 结构化样张
> 关联主线：`真实人生场景入口与人生沙盘模拟`
> 关联模块：`Problem Case`、`思想伙伴选配器`、`学习路径地图`、`能力路径`、`选题中台`

## 1. 本样张要验证什么

验证用户是否真的需要一个“升学全景地图”，而不是单纯的报考建议。

核心假设：

- 用户面对的是信息黑箱和未来不确定性；
- 用户需要的是先看全景，再做筛选；
- 用户需要把兴趣、能力、城市、路径和风险放在一起看；
- 用户愿意从这个入口进入系统，而不只是搜索学校名字。

## 2. 页面目标

让用户在 10-20 秒内理解：

- 这个系统不是代报志愿；
- 它是给你一个可筛选、可比较、可推演的全景地图；
- 它会把学校、专业、城市、路径和个人特点一起看。

## 3. 页面结构

### 3.1 顶部

- 标题：高考升学 / 选校
- 一句话说明：先看全景，再看适合什么
- 输入：学校 / 专业 / 城市 / 目标

### 3.2 中部

- 学校与专业全景地图
- 选择维度：兴趣、能力、城市、风险、路径
- 筛选结果：推荐比较的方向

### 3.3 右侧 / 下方

- 个人特点提示
- 推荐问题卡（Problem Case）
- 推荐思想伙伴视角
- 推荐学习路径与能力路径
- 最小行动

## 4. 这个样张的产品表达

### 4.1 不替代老师

明确写在页面里：

- 不是内幕答案；
- 不是报考代办；
- 不是唯一正确解。

### 4.2 但提供更大的 picture

系统提供的是：

- 全景；
- 维度；
- 比较；
- 风险；
- 自我定位。

## 5. 进入 Problem Case 的方式

可以把高考/选校场景转成如下问题对象：

- 我有哪些学校/专业值得比较？
- 我的兴趣和能力怎么匹配？
- 哪些维度更重要？
- 我现在最缺的判断信息是什么？

## 6. 最小行动

建议样张输出一个最小行动：

- 选出 3 所最想比较的学校；
- 选出 3 个最想比较的专业；
- 写出自己最在乎的 3 个维度。

## 7. 验收标准

- 用户能迅速理解这是一个全景入口；
- 用户能进行基础筛选；
- 页面能引导进入 Problem Case；
- 页面能引导到学习路径或能力路径；
- 不出现“我们替你做决定”的暗示。

## 8. 场景卡样例

| 字段 | 内容 |
| --- | --- |
| 场景 ID | `exam-school-selection` |
| 场景名称 | 高考升学与选校 |
| 用户原话 | “我不知道该选学校、选专业，感觉每个选择都会影响以后。” |
| 场景阶段 | 高中后期 / 志愿准备 / 升学规划 |
| 核心不确定性 | 不知道学校、专业、城市、未来路径和个人特点如何一起比较 |
| 用户真正需要 | 先看全景，再缩小比较范围 |
| 系统角色 | 全景地图 + 选择维度整理 + 风险提示 + 最小行动 |
| 边界 | 不代替填报志愿，不给内幕结论，不承诺结果 |

## 9. 页面样张结构

### 9.1 首屏

```text
高考升学 / 选校
先看全景，再看适合什么。

[输入学校/专业/城市/目标]
[我还不知道，先从兴趣和能力开始]

当前你可以先比较：
- 学校层次
- 专业方向
- 城市与生活
- 未来路径
- 风险与备选
```

首屏要让用户马上知道：

- 这里不是“替你报志愿”；
- 这里是把选择摊开；
- 你可以从模糊状态开始，不必一上来知道答案。

### 9.2 中部地图

| 地图区块 | 展示内容 | 目的 |
| --- | --- | --- |
| 学校维度 | 层次、地域、资源、就业/升学氛围 | 避免只看排名 |
| 专业维度 | 学科内容、能力要求、就业方向、转专业弹性 | 避免只看热门 |
| 城市维度 | 生活成本、产业机会、家庭距离、长期发展 | 把城市当作路径变量 |
| 个人维度 | 兴趣、优势科目、学习方式、风险承受 | 把用户放进地图 |
| 风险维度 | 信息不对称、热门拥挤、父母期待、分数波动 | 提前识别误判 |

### 9.3 右侧 / 下方承接

| 承接区 | 内容 |
| --- | --- |
| 当前问题命名 | “你现在不是缺答案，而是缺一张比较地图。” |
| 推荐 Problem Case | 学校/专业比较、兴趣能力匹配、家庭期待协调、信息黑箱判断 |
| 推荐思想伙伴 | 系统思考、长期主义、职业路径、家庭沟通视角 |
| 推荐学习路径 | 选择力、判断力、信息筛选、专业认知 |
| 推荐行动 | 先列出 3 所学校、3 个专业、3 个最在意维度 |

## 10. 全景地图样例

| 维度 | 需要比较的问题 | 常见误区 | 系统提示 |
| --- | --- | --- | --- |
| 学校 | 我更看重学校平台、专业资源还是城市机会？ | 只看名气，不看资源是否匹配 | 把学校拆成平台、资源、人群、路径 |
| 专业 | 这个专业到底学什么、需要什么能力？ | 把专业名误解成职业名 | 看课程、能力、去向和转向空间 |
| 城市 | 这个城市会给我什么机会和限制？ | 只看距离或印象 | 看产业、生活成本、实习机会 |
| 兴趣 | 我是真的喜欢，还是只是听起来体面？ | 把短期新鲜感当长期兴趣 | 用课程、任务和真实案例验证 |
| 能力 | 我的优势科目和学习方式适合吗？ | 用分数替代能力判断 | 区分成绩、能力、学习习惯 |
| 风险 | 如果第一选择不成立，有没有备选路径？ | 把一次选择当终局 | 设计 A/B/C 路径和复盘节点 |

## 11. Problem Case 映射

| Problem Case | 用户原话 | 适合输出 |
| --- | --- | --- |
| `school-major-compare` | “我到底该优先学校还是专业？” | 比较维度、权重表、风险提示 |
| `interest-ability-match` | “我也不知道自己到底喜欢什么。” | 兴趣验证任务、能力自查、专业样本 |
| `family-expectation-conflict` | “家里希望我选稳定，但我想看别的方向。” | 视角差异、沟通脚本、边界表达 |
| `information-blackbox` | “网上信息太多，我不知道该信谁。” | 信息源分级、证据清单、判断框架 |

## 12. 轻量沙盘推演样例

| 路径 | 短期收益 | 中期影响 | 隐藏成本 | 复盘问题 |
| --- | --- | --- | --- | --- |
| 冲学校平台 | 满足平台期待，选择看起来更稳 | 可能获得更大人群和资源 | 专业不匹配时学习痛苦 | 我能接受专业适配度降低吗？ |
| 专业优先 | 学习内容更可能匹配兴趣 | 后续深耕路径更清楚 | 学校平台可能弱一些 | 这个专业的真实任务我试过吗？ |
| 城市优先 | 实习、产业、生活体验更明确 | 更早接触目标行业 | 容易忽略学校/专业质量 | 这个城市和我的长期路径有关吗？ |
| 稳妥保底 | 降低录取风险 | 心理压力较小 | 可能失去探索弹性 | 保底方案里有没有可成长空间？ |

沙盘输出必须保持克制：

- 只展示可能后果；
- 不给唯一答案；
- 不把路径讲成命运；
- 每条路径都要有复盘问题。

## 14. 内容切口

这个样张也可以反向喂给小红书或内容中台：

| 切口 | 标题方向 |
| --- | --- |
| 信息黑箱 | 高考选校最难的不是分数，是不知道该比较什么 |
| 专业误读 | 很多人选专业，其实只是在选一个名字 |
| 家庭期待 | 家长和孩子吵的不是学校，是对风险的不同理解 |
