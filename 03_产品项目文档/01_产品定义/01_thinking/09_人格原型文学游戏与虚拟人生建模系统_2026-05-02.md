## 一、产品定义更新

原来的产品核心是“问题驱动知识工作流”：用户带着一个真实问题进入系统，系统帮助他拆解、找证据、形成最小行动，并回流为内容素材。

这次新增的产品核心是“人格原型驱动的人生建模”：系统不只处理问题本身，而是把问题放回一个人的生命史、关系史、家庭脚本、文学原型和规则场景中理解。

一句话定义：

> 把真实用户、文学人物原型和游戏规则放到同一个人生沙盘里，生成可讨论、可推演、可创作、可行动的虚拟人生模型。

## 二、为什么这是现有系统的关键升级

当前圆桌工作流已经能处理：

```text
真实问题 -> 圆桌拆解 -> 行动卡 -> 小红书素材
```

但它还比较依赖“当下表达”。当用户说“我总是不敢发”“我在关系里总是解释”“我总是被家庭评价牵走”时，真正重要的往往不是这句话本身，而是背后的长期模式。

所以需要新增一层：

```text
真实用户人格模型
-> 解释他的重复卡点
-> 生成更真实的虚拟用户
-> 让圆桌智能体更像在理解一个人
-> 让内容、故事、游戏和干预都更有生命感
```

## 三、系统对象

### 1. Virtual Person 虚拟人生模型

用于描述一个“处在问题中的人”。

核心字段：

- 基本身份：年龄、职业、关系状态、所处阶段。
- 当前处境：当下最痛的一个问题。
- 成长时间线：童年、学校、工作、亲密关系、重要失落、重要转折。
- 家庭脚本：家庭如何处理成功、失败、冲突、亲密、羞耻、边界。
- 代际线索：上一代的恐惧、愿望、牺牲、沉默如何被继承。
- 亲密关系脚本：靠近、逃开、讨好、控制、解释、冷处理等模式。
- 自我叙事：他如何讲述自己。
- 保护策略：这些模式曾经如何保护他。
- 发展边界：当前最小可练习的变化。

### 2. Archetype Kernel 文学原型内核

从小说、戏剧、传记、神话、影视人物中抽取，不直接复制情节，而是抽取结构。

核心字段：

- 原型名称；
- 来源文本；
- 核心处境；
- 欲望；
- 恐惧；
- 缺失；
- 防御方式；
- 关系脚本；
- 典型语言；
- 命运结构；
- 可移植内核；
- 版权/公版状态。

### 3. Scene Transplant 现代场景移植

把文学原型移植到现代处境里。

核心字段：

- 现代场景；
- 角色关系；
- 社会压力；
- 触发事件；
- 冲突升级路径；
- 可转化节点；
- 可生成内容形式。

### 4. Rule Set 游戏规则组

把心理模式放进可互动的规则里。

核心字段：

- 规则类型：资源有限、信息不对称、轮流发言、时间压力、联盟背叛、公开评价等。
- 玩家角色；
- 可见信息；
- 胜负条件；
- 惩罚/奖励；
- 冲突机制；
- 复盘问题。

### 5. Output Artifact 输出物

同一套建模可以输出多种产物：

- 用户画像；
- 圆桌对话脚本；
- 小红书图文选题；
- 文学趣味号选题；
- 小说人物设定；
- 短剧分镜；
- 桌游/互动故事机制；
- 心理成长练习卡。

## 四、系统架构

## 五、和现有产品页面的关系

### `/tools/roundtable`

圆桌工作流仍然是“干预和内容回流”的主页面。新增的人格原型系统为它提供更真实的虚拟用户和更深的前史。

### `/tools/problem-lab`

卡点工作台可以接入“这个卡点是否来自某个重复脚本”的判断。

### `/tools/content-ops`

选题中台可以多出一条“文学原型/现代移植”的内容生产线。

### `/tools/space-browser`

书籍地图未来可以从“书的地图”进一步长成“思想大陆 + 人物原型岛屿 + 游戏规则场”的混合世界。

### 新增 `/tools/archetype-lab`

最小原型页面，验证：

```text
文学原型 + 现代处境 + 游戏规则 -> 人格模型/内容选题/故事种子
```

## 六、专家评估框架

这个方向需要用专家来校准，不宜只靠产品直觉。

| 专家角色 | 主要校准问题 | 需要避免 |
|---|---|---|
| 心理动力学/精神分析 | 防御、早年关系、重复模式是否理解过浅 | 把人诊断化、病理化 |
| 家庭系统/萨提亚/鲍恩 | 家庭脚本、代际传承是否建模合理 | 把家庭问题简单归因给父母 |
| 叙事身份/发展心理学 | 自我故事、人生阶段、成长边界是否合理 | 把人格写死 |
| 文学研究/叙事学 | 原型抽取是否忠于文本复杂性 | 把文学人物工具化、标签化 |
| 游戏设计/严肃游戏 | 规则是否真的产生互动和选择压力 | 只做概念展示，不可玩 |
| AI/HCI/隐私伦理 | 用户材料、虚拟人、心理敏感信息如何保护 | 过度采集、误导性建议 |
| 内容策略 | 如何把深度研究转成有传播力的表达 | 为传播牺牲复杂性 |

## 七、可行性判断

### 技术可行

第一版不需要训练模型。可以先用结构化数据、规则模板和静态样张验证。

### 产品可行

它能直接增强当前已有的圆桌、卡点、选题、书籍地图四个页面。

### 内容可行

它能产生两条内容线：

- 严肃思考号：真实问题、心理机制、成长路径。
- 文学趣味号：文学人物进入现代处境，讲复杂人性。

### 风险较高

最大风险不是技术，而是伦理和表达边界：

- 不能伪装成心理诊断；
- 不能让用户误以为系统完全理解了他；
- 不能用真实隐私训练或展示虚拟人；
- 不能把文学人物粗暴变成流量标签；
- 不能把游戏化做成对痛苦的娱乐化。

## 八、阶段路线

### P0：静态最小原型

目标：验证三角结构是否成立。

功能：

- 选择文学原型；
- 选择现代处境；
- 选择游戏规则；
- 生成一张人格原型卡；
- 输出内容选题和故事种子。

### P1：文学原型库

目标：先用公版文本和本地可用素材做 20-50 张原型卡。

优先来源：

- 鲁迅、老舍等现代文学中已进入公版或授权明确的文本；
- 中国古典小说；
- 希腊神话、莎士比亚、陀思妥耶夫斯基等公版文本；
- Project Gutenberg、Wikisource、Internet Archive 等来源。

### P2：真实用户深度建模表单

目标：把真实用户材料收成结构化但不过度侵犯隐私的“生命史线索表”。

原则：

- 用户可跳过任何问题；
- 敏感内容默认本地保存；
- 输出使用“可能”“线索”“假设”，不用诊断语言；
- 每个画像都保留“我可能理解错了”的校正入口。

### P3：规则沙盘

目标：把人格原型放入规则场，做互动桌游/网页小游戏样张。

验证问题：

- 规则是否真的暴露模式；
- 玩家是否能从复盘中看见自己；
- 复盘是否能回到行动，而不是只停留在戏剧性。

### P4：研究与内容双循环

目标：让专家评审、真实用户反馈和内容数据进入同一个改进闭环。

```text
研究假设 -> 原型样张 -> 用户反馈 -> 内容发布 -> 数据回流 -> 模型修正
```

## 九、近期最小行动

1. 建一个 `/tools/archetype-lab` 静态页面，先验证产品形态。
2. 先做 4 个文学原型，不追求多：
   - 被共同体叙事吞没的人；
   - 用懂事换安全的人；
   - 在亲密关系中反复解释的人；
   - 把失败视为身份崩塌的人。
3. 每个原型只做 3 个现代移植场景。
4. 每个场景只接 3 个规则机制。
5. 找 3-5 个专家分别评审结构，而不是直接评审视觉。

## 十、内容前台：名著人物职场心理图鉴

2026-05-03 补充：`名著人物职场心理图鉴` 可以作为这个系统的第一个公开采样器。

它的定位不是“名著解读栏目”，而是：

> 用小红书的轻入口，验证文学原型、现代处境和组织规则能否被真实读者识别、收藏、评论和回流。

三层关系：

```text
小红书系列 = 公开验证入口
Archetype Lab = 结构化原型中台
人生沙盘 = 交互推演层
```

数据流：

```text
源作品/人物
-> 人物原型抽取
-> 世界规则抽取
-> 现代处境迁移
-> 小红书 10 页图文
-> 发布反馈/评论/收藏信号
-> 原型实验室结构化对象
-> 人生沙盘组合推演
-> 新选题/故事种子/复盘问题
-> 回到小红书继续验证
```

每篇内容至少沉淀：

- `SourceWork`：源作品、作者、人物、版权/可用范围；
- `ArchetypeKernel`：核心缺口、欲望、恐惧、保护策略、关系脚本、成长边界；
- `WorldSystem`：世界规则、资源、禁忌、惩罚、典型场景；
- `RuleSet`：规则压力、状态变量、复盘问题；
- `LifeScene`：现代场景、触发事件、冲突路径、可能行动；
- `OutputArtifact`：标题、封面钩子、10 页结构、标签；
- `FeedbackSignal`：共鸣句、误读句、案例句、下一人物提名、数据表现。

内容安全阀：

```text
不要说“某人物 = 某类人”。
要说“某人物显影了一种心理结构 / 关系处境 / 组织机制”。
```

例如：

```text
王熙凤不是控制狂女领导，
而是复杂组织如何把一个能人推成控制中枢。
```

这条内容线可以和 `/tools/content-ops` 打通：从每张 `ArchetypeKernel` 自动生成 4-0、4-2、小红书正文、评论区引导，再把评论回流到 `FeedbackSignal`。
