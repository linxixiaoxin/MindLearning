# 处境驱动相关页面：专家评审与内容重构

> 创建时间：2026-05-02  
> 关联主线：`42_人生处境地图_专家评审与新版布局规划.md`、`43_大型3D书籍地图_素材与书籍表意系统.md`  
> 关联页面：`/tools/life-scenes`、`/tools/problem-lab`、`/tools/thought-partner`、`/tools/learning-paths`、`/tools/space-browser`

## 1. 本轮评审结论

上一轮把 `/tools/life-scenes` 从“可视化实验台”收成了“人生处境地图”。这轮相关页面也需要沿同一条主线重排：

```text
处境地图
-> 卡点工作台
-> 思想伙伴
-> 练习路线
-> 书籍世界地图
```

专家组一致认为：这些页面不能再分别像“问题 demo、作者 demo、学习路径 demo、3D demo”。它们要像一套连续工具，帮助用户从一句真实处境一路走到可执行行动，再回到书和知识材料。

## 2. 参与评审视角

| 角色 | 关注点 | 主要判断 |
| --- | --- | --- |
| 产品策划 | 页面之间的主线、命名、入口关系 | 所有页面都要服务“从卡住到行动”，不要各自展示能力 |
| UX 信息架构 | 首屏理解、任务顺序、按钮文案 | 用户不应先理解系统术语，而应知道下一步点哪里 |
| 信息可视化专家 | 图形是否表达关系 | 可视化只保留能解释关系的部分，不能变成图形炫技 |
| 内容策略 | 后续选题和书籍材料如何接入 | 书籍、作者、路线都应是支撑材料，不抢走处境主线 |
| 3D 表意系统策划 | 书籍地图的远中近景语义 | 3D/2.5D 页面要从“书名点位”升级为“书籍主题世界” |

## 3. 页面定位重构

| 页面 | 原心智 | 新心智 | 本轮改名 / 文案方向 |
| --- | --- | --- | --- |
| `/tools/life-scenes` | 真实人生场景入口 | 处境地图总入口 | 说出处境、看维度、找卡点、比较走法、定小行动 |
| `/tools/problem-lab` | 问题工作台 / Problem Lab | 卡点工作台 | 把“我卡住了”拆成现场、情绪、需要、追问和行动 |
| `/tools/thought-partner` | 思想伙伴选配器 | 换镜头工具 | 给当前处境安排照亮、翻译、校准、行动的思考分工 |
| `/tools/learning-paths` | 学习路径地图 | 练习路线地图 | 从一个卡点走到书、概念、练习、输出 |
| `/tools/space-browser` | 关系型书库 / 3D 地球 | 书籍世界地图 | 远看领域地貌，近看书与处境、问题、路线的连接 |

## 4. 命名规则

本轮统一替换的原则：

| 不再优先使用 | 改为 |
| --- | --- |
| 真实场景 | 真实处境 / 处境地图 |
| 问题工作台 | 卡点工作台 |
| 学习路径 | 练习路线 |
| 思想伙伴选配器 | 思想伙伴 / 思考分工 |
| Visual POC | 路线图 / 结构图 |
| Mermaid POC | 结构图 |
| 3D 书库 | 书籍地图 / 立体书库 |
| 知识星系 | 关系星图 |
| 主题群岛 | 主题世界 |

关键原则：如果这个词更像研发、内部评审或功能展示，就不要放在用户第一层。

## 5. 新用户旅程

### 5.1 从处境到行动

```text
我现在卡住了
-> 我选一个最像自己的处境
-> 系统告诉我这件事要看哪几面
-> 我进入一个具体卡点
-> 我用卡点工作台拆清楚
-> 如果还想不动，就请思想伙伴换镜头
-> 如果知道要补什么，就进入练习路线
-> 如果要继续找材料，再进入书籍世界地图
```

### 5.2 页面之间的职责边界

- 处境地图：只负责接住用户和给出第一条链路。
- 卡点工作台：负责把模糊困惑拆成可工作的对象。
- 思想伙伴：负责换视角，不负责给最终建议。
- 练习路线：负责把理解变成书、概念、练习和输出任务。
- 书籍世界地图：负责展示材料世界，不抢主流程。

## 7. 仍需后续处理

### P0：补齐数据命名

部分数据文件里仍有历史名称，例如 `learningPathId` 作为内部字段可以保留，但用户可见的 `phaseLabel`、`outputFormats`、工具注册标题要继续改成“练习路线 / 卡点工作台”。

### P1：书籍地图继续做表意层

根据 43 号文档，下一版应继续推进：

```text
书名点位
-> 书籍主题世界
-> 领域地貌
-> 单书隐喻物件
```

但这属于 3D / 2.5D 表意实现，不能和并行页面的渲染实验互相覆盖。

### P2：每页补一句“我现在在哪”

后续每个页面顶部可以补一个轻量流程条：

```text
处境 -> 卡点 -> 换镜头 -> 练习 -> 找材料
```

让用户知道自己不是掉进一个孤立工具页，而是在一条连续路径里。

## 8. 当前决策

本轮不再扩展新视觉效果，而是先统一产品语言：

> 页面之间的关系，比单个页面炫不炫更重要。

只有当用户能清楚知道“我为什么从处境地图来到这里、这里帮我做什么、下一步去哪”时，视觉化才真正服务产品主线。

## 9. 2026-05-02 第二轮补充：当前旅程状态条

这轮新增一个跨主线页面的 `ExperienceFlowStrip`，作为五个核心页面之间的轻量状态参照：

```text
处境地图 -> 卡点工作台 -> 思想伙伴 -> 练习路线 -> 书籍地图
```

### 9.1 设计目标

- 用户不用记住页面关系，状态条会告诉他当前处在整条体验的哪一步。
- 每一步都显示最小输入和产出，例如“真实人生处境 -> 可拆解卡点”、“当前卡点 -> 一组可调用视角”。
- 状态条不再复制顶部栏目。顶部栏目负责全站导航，状态条只保留当前页、上一步、下一步、小进度点和输入/产出。

### 9.2 实现范围

- 新增组件：`web/src/components/ExperienceFlowStrip.vue`
- 接入位置：`web/src/App.vue`
- 出现页面：`处境地图`、`卡点工作台`、`思想伙伴`、`练习路线`、`书籍地图`
- 暂不触碰 2.5D / 3D 渲染、镜头、素材和交互逻辑，只把书籍地图纳入整体体验链路。

### 9.3 体验判断

这一步解决的是“逻辑关系看不出来”的问题。它不是再增加解释文字，而是给用户一个持续存在的结构参照：我从处境来，现在处理什么，下一步去哪。

### 9.4 移动端补充

检查移动端时发现，`卡点工作台` 的主体虽然已经会单列排列，但外层容器仍容易被内部内容撑宽，造成小屏横向溢出风险。本轮同步补了 `ProblemLab.vue` 的外层宽度、`box-sizing`、`min-width` 和横向溢出控制，让小屏优先保持可读。
