# 人生处境地图：专家评审与新版布局规划

> 创建时间：2026-05-02  
> 当前状态：v0.1 专家评审收敛稿 / 下一版改版依据  
> 关联页面：`/tools/life-scenes`  
> 关联代码：`web/src/components/SceneEntryHub.vue`、`web/src/components/scene-entry-hub.css`、`web/src/data/lifeSceneData.js`  
> 关联文档：`36_真实人生场景入口与人生沙盘模拟.md`、`41_问题人生场景驱动_视觉化程序复盘与外部参考.md`

## 1. 本轮评审结论

这版页面的问题不是“不够视觉化”，而是**视觉化抢走了产品主线**。

当前页面把“场景罗盘、旅程地图、节点流、系统循环、雷达坐标”放成并列模式，用户看到的是一组技术实验，而不是一条能读懂的处境处理路径。

专家评审一致认为：

> 下一版不要继续让用户在五种图形之间切换。  
> 页面应该从“可视化实验室”改成“人生处境处理台”。

用户第一眼要看懂的不是：

- 这是什么图；
- 这个图用了什么技术；
- 我应该选择哪种视觉模式。

而是：

- 我是不是在这个处境里；
- 这件事要看哪几面；
- 我真正卡住的问题是什么；
- 有哪几种走法；
- 今天先做哪一步。

## 2. 参与评审视角

本轮模拟了四类专家视角：

| 角色 | 关注点 | 核心判断 |
| --- | --- | --- |
| 人生场景产品策划 | 产品主线、入口命名、任务顺序 | 图形模式不该成为主控件，入口应改成“人生处境地图” |
| UX 信息架构专家 | 页面层级、阅读顺序、控件语义 | 页面现在像技术 demo，缺少 1-5 步的任务层级 |
| 信息可视化专家 | 图形语法、连线语义、视觉主从 | 线没有语义，很多关系靠 index 伪造，需要补真实关系数据 |
| 心理成长场景专家 | 用户语言、情绪承接、咨询感 | 首屏应先安抚，再澄清，最后给工具 |

## 3. 当前版本的主要问题

### 3.1 主对象不清楚

用户会分不清自己在做什么：

- 是选择人生场景？
- 是做诊断？
- 是看可视化图？
- 是打开问题卡？
- 是找书和学习路径？
- 还是进入内容选题中台？

原因是页面同时出现了：

- 左侧场景列表；
- 中间图形模式；
- 右侧维度 / 问题卡 / 沙盘 / 行动；
- 下方维度列表；
- 问题卡列表；
- 沙盘路径；
- 证据书籍；
- 内容切口；
- 技术实验卡。

这些模块没有被组织成清晰的“第 1 步、第 2 步、第 3 步”。

### 3.2 技术模式成了用户控件

当前页面暴露了这些内部或技术语言：

- `LifeScene.v0.2`
- `Problem-Life Scene`
- `Custom SVG`
- `Vue Flow 思路`
- `Kumu / Loopy`
- `ECharts 风格`
- `D1 / D2`
- `Sandbox`
- `Focus Dimension`
- `Ready / Next`

这些词适合研发评审，不适合用户第一屏。

用户不关心使用哪种图库或哪种图形范式，用户关心：

> 我现在该看哪里、点哪里、得到什么。

### 3.3 连线像装饰，不像关系

当前页面视觉上有线、有节点、有高亮，但数据层并没有明确声明：

```text
哪个维度
-> 对应哪个风险
-> 对应哪个问题卡
-> 对应哪条走法
-> 对应哪个行动
```

目前部分联动是用数组 index 取模形成的。这会产生一个问题：

> 界面暗示“岗位天然对应某张问题卡和某条路径”，但用户看不出为什么。

这也是用户说“逻辑关系看不出来”的核心原因。

### 3.4 首屏缺少情绪承接

真实人生场景入口不是普通工具页。用户往往是带着焦虑、混乱、不确定进来。

当前页面太快进入：

```text
地图
罗盘
问题卡
沙盘
路径
书籍
能力
选题
```

心理成长视角认为，正确顺序应该是：

```text
先安抚
-> 再澄清
-> 最后给工具
```

也就是先告诉用户：

> 你不需要马上确定答案。我们先把这件事拆清楚。

## 4. 入口命名重规划

### 4.1 主入口命名

建议把当前“问题人生场景地图”改为：

> **人生处境地图**

备选：

- 人生场景处理台
- 当前处境拆解器
- 从卡住到行动

推荐仍用“人生处境地图”。

原因：

- “处境”比“场景”更像用户语言；
- “地图”保留结构感；
- 能同时承接升学、求职、关系、家庭、转型等场景；
- 不像“问题人生场景”那样抽象堆叠。

### 4.2 主副标题建议

主标题：

```text
人生处境地图
```

副标题：

```text
从你现在卡住的那件事开始，不用先会提问。
我们先把它拆成：你在担心什么、有哪些选择、缺哪些信息、下一步能做什么。
```

更短版本：

```text
把你正在经历的事，拆成看得清、选得动、做得出的下一步。
```

## 6. 新版用户理解顺序

新版页面必须按用户任务组织，而不是按图形模式组织。

推荐主流程：

```text
1. 选择处境
2. 说清现在卡住的点
3. 看这件事要拆哪几面
4. 找到最可能的具体卡点
5. 比较几种走法
6. 定一个今天先做的小行动
7. 再进入书、能力路径和思想伙伴
```

更适合页面展示的短步骤：

```text
说出处境
-> 找到卡点
-> 看清影响因素
-> 比较几种走法
-> 定一个小行动
```

## 7. 新版页面布局

### 7.1 顶部

```text
人生处境地图
把你正在经历的事，拆成看得清、选得动、做得出的下一步。

步骤条：
1 选处境 -> 2 看关键维度 -> 3 找具体卡点 -> 4 比较走法 -> 5 今天先做一步
```

要求：

- 不展示版本号；
- 不展示技术名；
- 不展示视觉模式切换；
- 不放书库、选题中台等分流入口。

### 7.2 第一屏主体

布局：

```text
左侧：选择当前处境
中间：当前处境卡 + 处境拆解图
右侧：下一步建议
```

#### 左侧：选择当前处境

卡片不只写分类名，要写“我现在像不像这个”。

示例：

```text
想换工作，但不知道下一步怎么走
我不知道自己适合什么，也不知道该先补什么。
```

```text
选学校和专业，不知道该比较什么
感觉每个选择都会影响以后。
```

```text
一句话让我很难受，但说不清原因
我不知道这是事实、脑补，还是旧模式被触发。
```

#### 中间：当前处境卡

内容结构：

```text
标题：想换工作，但不知道下一步怎么走

安抚语：
不急着判断你适不适合，也不急着让你报课。
我们先把目标岗位、已有能力、可证明的证据和转型风险摆开看。

用户原话：
“我想换工作，但不知道自己适合什么，也不知道该先补什么。”

核心要处理：
看清岗位世界、能力差距和可证明成果。

边界：
不承诺 offer，不代替职业测评。
```

#### 右侧：下一步建议

内容结构：

```text
当前最可能的卡点
我缺什么能力，才能进入下一阶段？

进去后会得到
能力差距表、学习路径、练习任务

主按钮
进入问题工作台

次按钮
先看这件事要拆哪几面
```

### 7.3 第二屏：关键维度

模块标题：

```text
这件事要看哪几面
```

列表结构：

| 维度 | 要问的问题 | 容易误判 |
| --- | --- | --- |
| 岗位 | 这个岗位每天真正做什么，交付什么？ | 只看岗位标题，不看职责和协作对象 |
| 能力 | 我已有能力哪些能迁移，哪些必须补？ | 以为转型必须从零开始 |
| 证据 | 我有什么作品、项目或案例能证明能力？ | 简历堆经历，没有可验证证据 |
| 路径 | 直接转、内部转、先做作品集，哪个风险可承受？ | 被焦虑推着跳，而不是先做小验证 |
| 怎么讲经历 | 我的经历如何讲成目标岗位听得懂的话？ | 经历很散，无法形成可信转型故事 |

交互原则：

- 点击维度后，只更新“当前关注点”和“相关问题卡”；
- 不要自动把维度强行绑定到某条路径；
- 如果要连线，必须来自显式关系数据。

### 7.4 第三屏：具体卡点 / 问题卡

模块标题：

```text
你现在最像卡在哪个问题
```

每张卡结构：

```text
状态：可进入 / 建设中
问题：我缺什么能力，才能进入下一阶段？
适用情况：目标方向大概有了，但不知道差距在哪里
会产出：能力差距表、学习路径、练习任务
按钮：进入问题工作台
```

### 7.5 第四屏：三种走法 / 选择推演

模块标题：

```text
如果这样走，会发生什么
```

每条路径固定三项：

```text
走法：立刻投递
可能收益：快速获得市场反馈
可能代价：拒绝信号不一定告诉你问题在哪
复盘问题：我能从 10 次投递里提取什么信号？
```

```text
走法：先做作品集
可能收益：把能力变成证据，转型叙事更扎实
可能代价：需要明确截止日期，否则容易无限准备
复盘问题：7 天内能完成哪个最小作品？
```

```text
走法：先内部转岗
可能收益：收入风险更低，能借公司场景积累证据
可能代价：受组织机会限制
复盘问题：公司内部有没有可借力项目？
```

### 7.6 第五屏：今天先做一步

模块标题：

```text
这周不解决整个人生，只做一个可见动作
```

行动卡：

```text
1. 列出 3 个目标岗位
2. 对照出 3 个关键能力缺口
3. 写出 1 个作品集 / 简历 / 项目改进动作
```

视觉上要像行动区，而不是信息卡。

### 7.7 支撑材料下沉

书籍、学习路径、能力路径、思想伙伴、内容切口都放到下游。

推荐分组：

```text
继续深入
- 学习路径
- 能力路径
- 思想伙伴

支撑材料
- 相关书籍
- 关键概念

内容生产视角
- 小红书切口
- 选题中台
```

其中“内容生产视角”默认折叠，不放在用户任务主线中。

## 8. 视觉语法重规划

下一版不再让用户选择五种图。

主视觉保留一种：

> **人生处境地图**

它由以下元素构成：

| 元素 | 形状 | 含义 |
| --- | --- | --- |
| 中心大卡 | 大矩形 / 白板中心 | 我的原话 / 当前处境 |
| 关键维度 | 圆点 / 小卡 | 这件事要看的角度 |
| 风险盲区 | 琥珀提示 / 三角标签 | 容易误判的地方 |
| 具体卡点 | 矩形卡 | 可进入的问题 |
| 可能走法 | 分叉卡 | 三种可试的路径 |
| 今天行动 | 绿色行动条 | 当前最小动作 |
| 支撑材料 | 灰色小节点 | 书、学习路径、证据 |

### 8.1 连线语义

下一版每条线必须有语义。

| 线型 | 含义 |
| --- | --- |
| 蓝色实线 | 拆解：当前处境要从哪些角度看 |
| 橙色实线 | 误判：这个角度容易掉进什么坑 |
| 紫色箭头 | 转译：从维度转成具体卡点 |
| 绿色箭头 | 行动：从问题推进到今天一步 |
| 灰色点线 | 支撑：书籍、学习路径、证据材料 |
| 回环箭头 | 复盘：做完后回来看模式 |

页面图例可以非常短：

```text
圆点 = 要看的维度
警示 = 容易误判
卡片 = 具体卡点
分叉 = 三种走法
绿色 = 今天先做
```

### 8.2 一次只高亮一条链路

用户点击“能力”时，页面应该读成一句话：

```text
我想换工作
-> 先看能力
-> 容易误判：以为必须从零开始
-> 对应卡点：我缺什么能力，才能进入下一阶段？
-> 可能走法：先做作品集
-> 今天行动：对照 3 个关键能力缺口
```

这才是“关系”。

不是所有节点互相连，也不是线越多越好。

## 10. 求职转型样张新版文案

### 10.1 入口标题

```text
想换工作，但不知道下一步怎么走
```

### 10.2 副标题

```text
不急着判断你适不适合，也不急着让你报课。
我们先把目标岗位、已有能力、可证明的证据和转型风险摆开看。
```

### 10.3 澄清问题

```text
你现在最像哪一种卡住？
```

选项：

- 我不知道自己适合什么岗位；
- 我想转型，但怕从零开始；
- 我投了简历没反馈；
- 我不知道该先补什么能力；
- 我讲不清自己的经历有什么价值。

### 10.4 教练式流程

```text
1. 先说清现在的处境
用一句话说：你为什么想换？是厌倦现在、看不到成长，还是被目标岗位吸引？

2. 找到真正卡点
你现在的问题可能不是“没有方向”，而是方向、能力、证据、风险里有一块没被看清。

3. 看目标岗位真实在做什么
先别只看岗位名称。我们看它每天做什么、交付什么、和谁协作、怎么被评价。

4. 盘点你已经能迁移的能力
你不是从零开始。我们从过去的项目、沟通、分析、执行、管理经验里，找能迁移到目标岗位的部分。

5. 找出还缺的证据
面试官不会只听你说“我能做”，他需要看到案例、作品、项目结果或具体表达。

6. 比较三种走法
立刻投递：先拿市场反馈。
先做作品集：把能力变成证据。
先内部转岗：降低收入风险，借现有场景积累案例。

7. 定一个 7 天行动
这周不解决整个人生，只完成一个可见动作：拆 3 个目标岗位 JD、改一段简历证据，或做一个最小作品。
```

## 11. 下一版实现优先级

### P0：去技术化

- 移除用户端视觉模式切换；
- 移除 `Custom SVG / Vue Flow / Kumu / ECharts` 等技术词；
- 隐藏 `LifeScene.v0.2`；
- 替换页面标题和流程文案。

### P1：重排第一屏

- 左侧：选择处境；
- 中间：当前处境卡 + 处境拆解；
- 右侧：下一步建议；
- 顶部步骤条按用户任务展示。
