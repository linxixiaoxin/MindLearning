# 问题人生场景驱动：视觉化程序复盘与外部参考

> 创建时间：2026-05-02  
> 当前状态：v0.1 复盘与下一轮探索建议  
> 关联页面：`/tools/life-scenes`、`/tools/learning-paths/career-skill-map`  
> 关联文档：`36_真实人生场景入口与人生沙盘模拟.md`、`37_真实人生场景入口与人生沙盘模拟_系统结构图.md`、`38-40_真实人生场景样张`

## 1. 本轮结论

这轮实验已经证明：视觉化本身是有帮助的，但当前主视觉还停留在“学习路径地图”上。

现在产品主线已经改成：

```text
真实人生场景
-> 问题识别
-> 场景全景地图
-> 人生沙盘推演
-> 最小行动
-> 复盘成长
```

因此下一轮视觉化重点不应该继续把 `L0-L5` 学习路径做得更漂亮，而应该把 `/tools/life-scenes` 升级成一个真正的“场景地图程序”。

一句话判断：

> 学习路径图是下游；真实人生场景地图才是新入口。

## 2. 已做实验复盘

### 2.1 Mermaid 结构图

适合：

- 产品结构说明；
- 研发沟通；
- 文档里的系统流转；
- 快速表达对象关系。

不适合：

- 作为用户主页面；
- 承载复杂交互；
- 表达情绪、风险、选择压力；
- 做成小红书图感的视觉入口。

判断：

> Mermaid 保留为内部结构图和文档辅助，不作为用户第一视觉。

### 2.2 学习路径路线图

当前 `LearningPathMap.vue` 已经实现了路线图、雷达图、中心结构、词云等视觉 POC。

路线图适合表达：

- 从 `L0` 到 `L5` 的推进顺序；
- 用户从理解到练习再到输出的路径；
- 学习阶段之间的关系。

但它的问题是：

- 默认用户已经进入了某条学习路径；
- 默认中心对象是“能力成长”，不是“真实处境”；
- 对“我现在卡在什么人生场景”承接不足。

判断：

> 路线图适合作为 Problem Case 之后的二级页面，而不是新主入口。

### 2.3 能力雷达图

适合：

- 表达能力缺口；
- 展示用户当前强弱项；
- 支撑职业转型、沟通能力、选择能力等主题；
- 作为诊断结果或路径建议的辅助图。

不适合：

- 解释一个复杂人生场景的前因后果；
- 承载路径分叉；
- 直接替代全景地图。

判断：

> 雷达图应该放在“问题进入后”的能力诊断区，而不是场景入口顶部。

### 2.4 中心结构图

适合：

- 一个中心问题向外展开多个维度；
- 表达“场景 - 维度 - 风险 - 行动”的关系；
- 转化成下一版“场景罗盘”。

当前问题：

- 视觉中心仍是“能力中心”；
- 外圈节点仍是学习路径节点；
- 没有直接绑定 `LifeScene.mapDimensions`、`problemCases`、`simulationPaths`。

判断：

> 中心结构图是最值得保留并迁移到 `/tools/life-scenes` 的视觉形态。

### 2.5 词云

适合：

- 小红书选题；
- 情绪入口；
- 共鸣词捕捉；
- 内容翻译和视觉钩子。

不适合：

- 承载选择路径；
- 展示因果关系；
- 解释行动优先级。

判断：

> 词云适合放在“内容翻译 / 小红书图文生成”侧，不适合做产品主导航。

## 3. 外部参考扫描

### 3.1 Journey Map / Experience Map

代表参考：

- Nielsen Norman Group: Journey Mapping 101  
  https://www.nngroup.com/articles/journey-mapping-101/

可借鉴点：

- 用阶段表达一个人完成目标的过程；
- 同时展示行为、想法、情绪、痛点、机会点；
- 很适合“真实人生场景 -> 阶段 -> 卡点 -> 行动”的产品表达。

对本产品的启发：

```text
触发
-> 不确定
-> 拆解维度
-> 看到路径
-> 选择最小行动
-> 复盘
```

这比单纯知识图谱更贴近用户的真实体验。

### 3.2 Node-based UI / Flow Editor

代表参考：

- Vue Flow  
  https://vueflow.dev/
- React Flow  
  https://reactflow.dev/

可借鉴点：

- 节点、连线、缩放、拖拽、minimap；
- 很适合表达“问题卡 -> 推演路径 -> 行动结果”；
- 可以让用户看见一个问题如何分叉成多个路径。

对本产品的启发：

```text
LifeScene 节点
-> ProblemCase 节点
-> SandboxPath 节点
-> MinimumAction 节点
-> Review 节点
```

短期不一定马上引入库，但这个交互模型值得吸收。

### 3.3 Graph Visualization / 知识图谱

代表参考：

- AntV G6  
  https://github.com/antvis/G6
- Cytoscape.js  
  https://js.cytoscape.org/

可借鉴点：

- 适合复杂关系网络；
- 可以表达书、概念、问题、能力、作者之间的关系；
- 适合知识资产层，不一定适合人生场景的第一屏。

对本产品的启发：

> 知识图谱适合作为“证据网络”和“书籍关联层”，不要抢走场景入口的位置。

### 3.4 Chart / Data Visualization

代表参考：

- Apache ECharts  
  https://echarts.apache.org/examples/en/index.html

可借鉴点：

- 雷达图、桑基图、树图、关系图、路径图都成熟；
- 适合快速验证图表型视觉；
- 如果后续需要稳定图表组件，可以优先评估。

对本产品的启发：

- 能力雷达可以用 ECharts；
- 路径流转可以考虑桑基图；
- 层级结构可以考虑树图；
- 但场景罗盘这种强定制视觉，短期仍适合手写 SVG。

### 3.5 Systems Mapping / 因果循环

代表参考：

- Kumu Systems Mapping  
  https://docs.kumu.io/disciplines/system-mapping
- Loopy by Nicky Case  
  https://github.com/ncase/loopy

可借鉴点：

- 适合表达反馈循环、反复模式、关系系统；
- 特别适合“关系与沟通”“自我模式识别”“家庭协作”场景；
- 能帮助用户看到不是单点问题，而是一套互动循环。

对本产品的启发：

```text
触发
-> 解释
-> 情绪反应
-> 表达方式
-> 对方反应
-> 旧模式加固 / 新模式松动
```

这条视觉线可以成为关系类场景的特色形态。

### 3.6 Whiteboard / Infinite Canvas

代表参考：

- tldraw  
  https://github.com/tldraw/tldraw
- Excalidraw  
  https://github.com/excalidraw/excalidraw

可借鉴点：

- 手绘感强；
- 适合自由摆放、批注、草图化探索；
- 适合内部探索和小红书视觉风格实验。

对本产品的启发：

> 可以借鉴它们的“低压、手绘、可移动卡片”气质，但不建议一开始把产品做成完整白板工具。

### 3.7 Text-to-diagram / Markdown-to-map

代表参考：

- Mermaid  
  https://github.com/mermaid-js/mermaid
- Markmap  
  https://markmap.js.org/

可借鉴点：

- 快速从文字生成结构图；
- 适合文档、内部生产、Prompt 输出；
- 对自动化内容生产友好。

对本产品的启发：

> Mermaid / Markmap 可以作为“后台生成结构草图”的能力，不一定直接作为用户端最终视觉。

## 4. 新的视觉产品判断

真实人生场景驱动下，用户最需要的不是先看到知识关系，而是先回答四个问题：

1. 我现在在哪个处境里？
2. 这个处境有哪些关键维度？
3. 我真正卡住的问题是什么？
4. 今天我可以先做哪一个小动作？

因此主视觉应该从“知识图谱”转成“情境地图”。

推荐的视觉语法：

```text
真实原话
-> 场景罗盘
-> 问题卡入口
-> 沙盘分支
-> 最小行动
-> 复盘回路
```

## 5. 下一版 POC：场景罗盘

建议优先升级 `/tools/life-scenes`，不要继续在学习路径页上堆视觉。

### 5.1 第一屏结构

```text
左侧：场景切换
中间：场景罗盘
右侧：问题卡入口
底部：沙盘路径 + 最小行动
```

### 5.2 场景罗盘结构

```text
中心：
用户真实原话 / 当前处境

第一圈：
场景关键维度
例如：岗位、能力、证据、路径、叙事

第二圈：
风险 / 盲区
例如：只看岗位标题，不看真实交付

外侧：
可进入的问题卡

下方：
三条沙盘路径
例如：立刻投递 / 先做作品集 / 先内部转岗

最底部：
今天的最小行动
```

### 5.3 交互建议

- 点击维度：高亮相关风险、问题卡和沙盘路径；
- 点击问题卡：进入 `Problem Case`；
- 点击沙盘路径：展开短期效果、隐藏成本、复盘问题；
- 点击最小行动：进入行动记录或复盘入口；
- 保留书籍和学习路径作为“证据层”，不要放在第一视觉中心。

当前 `lifeSceneData.js` 已经有这些字段：

这样视觉层就不只是展示文字，而能真正联动。

## 7. 技术路线建议

### 7.1 短期

使用 Vue + 自定义 SVG。

原因：

- 当前项目已经是 Vue；
- 场景数量少；
- 视觉需要强定制；
- 不需要拖拽编辑；
- 可以最快验证“场景罗盘”是否成立。

### 7.2 中期

如果需要节点拖拽、缩放、连线、minimap，再评估 `@vue-flow/core`。

适合场景：

- 用户自己编辑人生沙盘；
- 问题卡之间出现复杂依赖；
- 需要保存用户自定义地图。

### 7.3 长期

如果要做知识网络、书籍概念图谱、作者思想关系，可以评估 AntV G6 或 Cytoscape.js。

这些更适合“知识资产层”，不是当前场景入口 MVP 的第一优先级。

## 9. 第一版落地建议

优先选 `求职与职业转型` 作为第一张场景罗盘样张。

原因：

- 数据已经比较完整；
- 维度清晰：岗位、能力、证据、路径、叙事；
- 沙盘路径明确：立刻投递、先做作品集、先内部转岗；
- 容易验证“场景 -> 问题卡 -> 学习路径”的完整链路。

第一版验收标准：

- 用户第一眼能看出这是一个“人生处境地图”，不是普通知识列表；
- 能从中心原话看到周围维度；
- 能从维度进入问题卡；
- 能看到至少三条可推演路径；
- 能看到今天的最小行动；
- 学习路径和书籍证据被放在下游，不抢主视觉。

## 10. 当前决策

本轮先不动 2.5D / 3D 页面。

下一轮视觉化程序优先级：

```text
P0：/tools/life-scenes 场景罗盘 POC
P1：沙盘路径卡片联动
P2：Problem Case 入口联动
P3：能力雷达下沉到学习路径 / 能力路径
P4：词云下沉到内容翻译 / 小红书视觉输出
```

最终方向：

> 不是把知识画成图，而是把一个人真实处境里的选择、风险、问题和行动画出来。
