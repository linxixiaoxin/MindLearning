# 大型 3D 书籍地图重构调研与素材方案

日期：2026-05-02

## 一、重新判断

当前版本的问题不是单纯“不够 3D”，而是把地图、书籍、标签、镜头、地标和数据关系都塞进一个 WebGL 组件里硬调。这样会导致：

- 书名在远景看不清，近景又遮挡。
- 地图缺少“巨大世界”的层级感。
- 地标虽然是 3D 几何体，但没有统一素材风格。
- 镜头飞行是手写 lerp，缺少成熟相机控制的距离、边界和过渡管理。

参考原视频，更合理的判断是：它不是全量真实 3D 建模，而是“超大插画地图 / 地形底座 + 少量 3D 地标 + 语义缩放标签 + 镜头巡游”。真正让它显得大的，不是每个元素都建模，而是地图尺度、层级、标签显隐和镜头运动。

## 二、GitHub / 成熟做法参考

### 1. 大地图 / 地形分块

- `geo-three`
  - 链接：https://github.com/tentone/geo-three
  - 价值：它用 three.js 做 tile-based 地图，支持世界级地图分块、地形高度数据和多地图服务。
  - 对我们的启发：如果要做“大地图感”，底层应按 chunk / tile 管理，而不是一个超大 plane 上画完所有东西。

- `three-tile`
  - 链接：https://github.com/sxguojf/three-tile
  - 价值：轻量 3D 瓦片地图，定位是把 3D 地形模型嵌到 three.js 应用里。
  - 对我们的启发：不一定要用 GIS，但可以借它的分块、LOD、低资源消耗思路。

### 2. 程序化场景生成

- `city-tour`
  - 链接：https://github.com/jstrait/city-tour
  - 价值：先生成 terrain map、道路、地块、建筑，再转成 3D 模型，并支持类似 Google/Apple Maps 的导航和自动 tour。
  - 对我们的启发：书籍地图应该先有“世界蓝图”，再渲染成 3D，而不是直接按点位堆 mesh。

### 3. 镜头飞行

- `camera-controls`
  - 链接：https://github.com/yomotsu/camera-controls
  - 价值：支持 `setLookAt`、`fitToBox`、`fitToSphere`、平滑过渡、边界限制。
  - 对我们的启发：不要继续手写相机 lerp。点击书籍后飞过去、框住某个岛屿、自动巡游，都应该交给成熟相机控制库。

### 4. 标签系统

- Three.js `CSS2DRenderer`
  - 文档：https://threejs.org/docs/#examples/en/renderers/CSS2DRenderer
  - 源码：https://github.com/mrdoob/three.js/blob/master/examples/jsm/renderers/CSS2DRenderer.js
  - 价值：用于把 HTML 标签挂到 3D 对象上。
  - 对我们的启发：书名、区域名、简介卡不应该烘焙进 Canvas 贴图。它们应该是独立标签层，按距离、层级、选中状态显隐。

- `three-spritetext`
  - 链接：https://github.com/vasturiano/three-spritetext
  - 价值：用 Sprite 渲染 Three.js 文本，始终朝向镜头。
  - 对我们的启发：适合少量 3D 内标签，但中文长标题仍要谨慎。

- `troika-three-text`
  - 链接：https://github.com/protectwise/troika/tree/main/packages/troika-three-text
  - 价值：SDF 文字，支持高质量 3D 文本、抗锯齿、多语言、光照和阴影。
  - 对我们的启发：如果要在 3D 场景内放清晰中文标题，优先考虑 Troika，而不是 CanvasTexture。

## 三、推荐新方案

### 方案 A：大型插画知识地图 + 3D 地标 + DOM 标签

这是最接近原视频的方案，推荐。

结构：

- 背景层：一张超大地图纹理，或者 4-8 个地图 tile。
- 地形层：低起伏 heightfield，不追求真实山体，只提供光影和透视。
- 岛屿层：每个知识区是实体岛屿台地，带边缘、阴影和色块。
- 地标层：少量 glTF 低模地标，比如金字塔、门、灯塔、塔、书堆、卷轴。
- 书籍层：书不是全部显示书名，远景显示书脊 / 小图标，中景显示短名，近景显示完整卡。
- 标签层：DOM / CSS2D 负责文字，做语义缩放和避让。
- 镜头层：camera-controls 负责 overview、island、book 三档飞行。

视觉原则：

- 远景只看大陆区块和大标题。
- 中景看岛屿、路线和重点书。
- 近景才显示单本书简介。

### 方案 B：全 3D 低模世界

可做，但不推荐作为第一版。

问题：

- 素材工作量明显更大。
- 中文书名仍然不能靠 3D 模型解决，还是要标签系统。
- 容易变成“玩具沙盘”，不一定像原视频的文学地图。

### 方案 C：真实 GIS / 地图瓦片

不推荐。

原因：

- 我们不是地理地图，而是知识地图。
- Mapbox / Cesium / GIS tile 会带来过重的坐标、服务、版权和性能问题。

## 四、可用素材来源

### 1. Kenney

- All-in-1：https://kenney.itch.io/kenney-game-assets
- Tower Defense Kit：https://kenney-assets.itch.io/tower-defense-kit
- 特点：风格统一，低模，含 2D、3D、字体、音效等，很多包是 CC0。
- 可用素材：地块、塔、树、道路、桥、基础建筑、图标。
- 适合：搭知识岛屿的基础地貌和统一风格。

### 2. Quaternius

- Ultimate Platformer Pack：https://quaternius.itch.io/ultimate-platformer-pack
- Fantasy Props MegaKit：https://quaternius.itch.io/fantasy-props-megakit
- 特点：大量低模 glTF / OBJ / FBX，CC0，适合游戏场景。
- 可用素材：书、卷轴、桌子、箱子、树、石头、桥、平台、市场摊位。
- 适合：书籍地图的地标、书堆、知识驿站、主题建筑。

### 3. Poly Pizza

- 链接：https://poly.pizza/
- 特点：大量低模模型，可按模型找素材。
- 注意：每个模型要单独看 license，不要默认全是 CC0。
- 可用素材：金字塔、骆驼、灯塔、门、书、岛屿、地图道具。

### 4. 自制素材

适合保留：

- 书块、书脊、卡片底座。
- 路线、光圈、选中态。
- 大地图纹理。

原因：这些和产品数据绑定强，直接用代码生成更灵活。

## 五、下一版实施切片

### P0：停止修旧 atlas，开一个新组件

建议新建：

- `SpaceAtlas3D.vue`
- `atlasScene.ts`
- `atlasCamera.ts`
- `atlasLabels.ts`
- `atlasAssets.ts`
- `atlasData.ts`

旧 `SpaceBrowser.vue` 保留入口和数据传递，不继续塞所有 3D 逻辑。

### P1：先做“原视频感”的最小闭环

只做 6 个岛、12 本书、6 个地标：

- overview：看到整张大地图。
- click island：飞到主题岛。
- click book：飞到单本书，右侧 / 左侧出现简介。
- labels：远景隐藏书名，中景显示短名，近景显示完整名。

### P2：引入依赖

建议新增：

- `camera-controls`：镜头飞行。
- `troika-three-text` 或 `three-spritetext`：3D 内文字。
- `GLTFLoader`：Three.js 自带 addon，不用额外 npm 包。

### P3：引入素材

先只放 10-20 个 glTF 小资产进：

- `web/public/atlas-assets/models/`
- `web/public/atlas-assets/textures/`
- `web/public/atlas-assets/licenses/`

每个外部素材都保留来源和 license。

## 六、结论

下一版不要追求“所有东西都真 3D”。真正的方向是：

> 大型知识地图的空间叙事 + 少量真实 3D 道具 + 成熟镜头飞行 + 标签层级管理。

这会比继续把书名贴到 3D 盒子上更接近原视频。
