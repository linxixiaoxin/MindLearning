# 新增想法：3D 地球书库与空间浏览器

> 创建时间：2026-05-01  
> 最近更新：2026-05-01  
> 当前状态：新想法收敛稿 / MVP 候选
> 来源：用户希望复刻视频里的 3D 地球书库效果
> 关联产品：书库首页、专题页、书的世界、认知地图入口

## 1. 总判断

这个想法不是“做一个炫酷 3D 特效”，而是做一个**空间化的知识入口**：把书、地点、主题、标签放进一个可旋转、可缩放、可点击的 3D 世界里，让用户用“探索”而不是“检索”进入内容。

它更适合作为：

- 书库首页的高识别入口；
- 专题页的沉浸式浏览模式；
- “书的世界”或“认知地图”的一种空间化表现；
- 旅行、地点、作者网络等内容的可视化容器。

不建议一开始就把它做成全站默认首页。先做一个可切换入口，验证用户是否真的愿意在这个空间里逛。

## 2. 产品定位

### 2.1 这是什么

一个基于 3D 场景的内容浏览器：

```text
内容数据 -> 坐标化 -> 3D 场景渲染 -> 旋转 / 缩放 / 点击 -> 信息卡 / 详情页
```

### 2.2 这不是什么

- 不是复杂的游戏；
- 不是重型三维编辑器；
- 不是管理后台；
- 不是要替代现有 `/books` 列表页的全部功能。

## 3. 目标用户

| 用户类型 | 典型需求 |
| --- | --- |
| 书库探索型用户 | 想从“逛一逛”进入内容，而不是先搜关键词 |
| 视觉敏感型用户 | 对平面列表没有耐心，但对空间关系有感觉 |
| 内容创作者 | 想把知识、地点、主题做成可传播的视觉入口 |
| 产品观察者 | 想看知识产品如何做出差异化入口 |

## 4. MVP 体验

### 4.1 核心流程

```text
进入 3D 地球首页
-> 拖动旋转世界
-> 放大缩小查看局部内容
-> 点击某个书/点位/标签
-> 弹出信息卡
-> 进入书页 / 专题页 / 相关主题页
```

### 4.2 第一版必须有的能力

- 地球或球体主视觉；
- 可拖动旋转；
- 可缩放；
- 点位 / 书卡 / 标签可见；
- 点击命中测试；
- 悬浮或侧边信息卡；
- 点击卡片可跳转详情页；
- 移动端可基本使用。

### 4.3 第一版不做的事

- 不做复杂物理模拟；
- 不做海量实时 3D 模型；
- 不做用户自定义编辑世界；
- 不做完整 3D 关卡式导航；
- 不把所有书都强行挂在同一层球面上。

## 5. 页面结构建议

### 5.1 首页结构

| 区域 | 内容 |
| --- | --- |
| 顶部 | 标题、搜索、视角切换入口 |
| 中央 | 3D 地球 / 空间主视图 |
| 浮层 | 当前选中内容的信息卡 |
| 底部 | 视图切换、筛选、缩放提示 |

### 5.2 信息卡结构

点击某个点位后，展示：

- 名称
- 类型（书 / 地点 / 主题 / 作者）
- 一句话说明
- 相关标签
- 进入详情按钮
- 相关内容推荐

## 6. 数据模型建议

建议把数据抽成统一结构：

```json
{
  "id": "book-xxx",
  "type": "book | topic | place | author",
  "title": "...",
  "subtitle": "...",
  "lat": 0,
  "lng": 0,
  "radius": 1,
  "category": "...",
  "tags": ["..."],
  "cover": "...",
  "targetUrl": "/books/...",
  "priority": 1
}
```

如果不是严格地理坐标，也可以先用：

- 球面经纬度；
- 环形分布；
- 主题簇分区；
- 固定热点位点。

## 7. 技术建议

### 7.1 推荐实现路径

**网页端优先。**

第一版建议：

- 前端：Vue 或 React
- 3D：Three.js / React Three Fiber
- 动画：GSAP / Tween.js
- 数据：本地 JSON / API

### 7.2 为什么先做网页

- 开发快；
- 分享方便；
- 便于先验证需求；
- 适合把它做成一个可传播的专题入口；
- 后面如果验证成立，再考虑 App 化。

### 7.3 App 是否需要

App 不是不能做，而是**不必一开始就做**。

如果后续证明这个入口的停留和转化足够强，再考虑：

- Flutter；
- SwiftUI + SceneKit；
- Unity / 原生 3D 方案。

## 8. 与现有模块的关系

### 8.1 可以承接的模块

- `/books`：作为内容总库入口的视觉升级；
- `/topics`：专题页可以进入空间化浏览模式；
- `书的世界`：单书页可延伸成书与书之间的空间关系；
- `学习路径地图`：路径节点可挂成空间路径；
- `思想伙伴选配器`：结果卡里的作者、书和主题可回流到这个世界里。

### 8.2 适合的内容类型

- 作者群；
- 主题群；
- 地点 / 旅行内容；
- 书籍网络；
- 认知地图；
- 多入口专题。

## 9. 风险与边界

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| 太炫但不好用 | 用户觉得酷，但找不到内容 | 保留搜索、筛选、详情承接 |
| 性能压力 | 3D 场景在低端设备上卡顿 | 控制点位数量，做降级模式 |
| 内容过密 | 球体上塞太多点位看不清 | 做分层、聚类、缩放揭示 |
| 没有探索价值 | 只像装饰动画 | 强化点击后的内容跳转与推荐逻辑 |
| 移动端操作困难 | 拖动和点击互相冲突 | 做明显的手势提示与容错 |

## 10. 版本建议

### v0.1

- 1 个 3D 地球主视图；
- 20-50 个内容点；
- 可旋转、缩放、点击；
- 点击弹信息卡；
- 跳转到现有详情页。

### v0.2

- 按主题分簇；
- 支持搜索和筛选；
- 支持视角切换；
- 支持书、地点、主题、作者四类点位；
- 支持“专题世界”切换。

### v1.0

- 形成稳定的空间化知识入口；
- 与书库、专题页、学习路径形成互链；
- 作为产品的差异化视觉资产。

## 11. 验收标准

1. 用户能在 10 秒内明白这是一个可探索的内容世界；
2. 用户能顺利拖动、缩放、点击至少 80% 的点位；
3. 点击后信息卡能清楚展示内容并跳转；
4. 移动端不至于完全不可用；
5. 至少一组真实用户反馈认为“比普通列表更有探索感”。

## 12. 结论

这个方向值得做，但要把它当作**知识站的空间入口实验**，而不是重做一个 3D 炫技产品。

最合理的第一步，是先做一个网页端小样，验证“内容能不能被空间化地浏览”。
