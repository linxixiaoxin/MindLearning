## 1. 一句话架构

`book-kb-multi` 是一个静态内容驱动的多书知识站，外加一组问题驱动的前端产品实验工具。

它当前不是传统“前端 + 后端 + 数据库”的平台，而是：

```text
本地书籍 / 结构化知识资产
-> 配置与半自动脚本
-> web/public 静态书籍包、专题包、注册表和素材
-> Vue + Vite 前端读取并渲染
-> Netlify 静态部署
-> 可选 Netlify Function AI 洞察
-> 可选本地 Codex bridge 内部协作
```

核心判断：

- 保留 `Vue 3 + Vite + 静态 JSON/Markdown` 作为当前验证栈。
- 继续用静态内容分发承接多书知识站，不急着上数据库。
- 研发重点从“继续堆页面”转为“内容生成、schema 校验、组件拆分、发布门禁、测试基线”。
- 本地 Codex bridge 只服务内部协作，不作为普通用户线上依赖。

## 6. 核心业务链路

### 6.1 多书阅读链路

```text
用户打开 /books
-> BookLibrary.vue 读取 registry
-> 选择书籍
-> loadBookBundle(slug)
-> HomeView / KnowledgeGraph / ArticleReader
-> file-map 定位 Markdown
-> marked + DOMPurify 渲染阅读内容
```

关键风险：

- `file-map.json` 指向不存在的 Markdown。
- `graph.links` 指向不存在节点。
- Markdown frontmatter 或 wiki-link 格式不一致。
- 内容卡保留内部结构化痕迹，不适合公开阅读。

当前护栏：

- `web/scripts/validate-site.mjs` 检查 registry、书籍 bundle、topic、graph、file-map、资产路径、HTML placeholder。
- `ArticleReader.vue` 已做 Markdown HTML 净化。

## 7. AI 与本地 bridge

### 7.1 Netlify Function

文件：

```text
web/netlify/functions/thought-partner-insight.mjs
```

用途：

- 接收思想伙伴行动反馈。
- 调用 OpenAI Responses API。
- 要求返回结构化 JSON schema。
- 输出 `pattern`、`reading`、`nextAction`、`tags`。

环境变量：

| 变量 | 必需 | 用途 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 是 | 调用 OpenAI API |
| `OPENAI_MODEL` | 否 | 覆盖默认模型；代码默认 `gpt-4.1-mini` |

边界：

- 不做心理诊断。
- 不输出医疗、法律、金融建议。
- 错误响应不能泄漏 prompt、key 或完整内部上下文。

### 7.2 本地 Codex bridge

文件：

```text
web/scripts/codex-insight-bridge.mjs
```

默认端口：

```text
127.0.0.1:8787
```

主要用途：

- 思想伙伴工具把结构化 payload 写入本地 `codex-inbox`。
- 页面可以轮询 response。
- 本地页面可以向 Codex 写入中台指令。
- 供研发协作，不作为普通用户线上功能。

主要文件：

```text
web/codex-inbox/thought-partner-latest.json
web/codex-inbox/thought-partner-response.json
web/codex-inbox/codex-command-latest.json
web/codex-inbox/codex-command-response.json
web/codex-inbox/codex-command-status.json
web/codex-inbox/codex-agent-heartbeat.json
```

### 7.3 Codex agent daemon

文件：

```text
web/scripts/codex-agent-daemon.mjs
```

默认定位：

- 读取 `codex-command-latest.json`。
- 调用本地 `codex` CLI。
- 默认 `reply-only` 模式。
- 不能声称自己改文件或执行本地命令，除非真实执行。

环境变量：

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `CODEX_CLI_BIN` | `codex` | Codex CLI 路径 |
| `CODEX_AGENT_CWD` | RedBook 根目录 | agent 工作目录 |
| `CODEX_AGENT_SANDBOX` | `read-only` | agent CLI 沙盒 |
| `CODEX_AGENT_MODEL` | 空 | 指定模型 |

## 10. 开发约束

1. 新增书籍或专题时，先确认 `registry/books.json`、`public/books`、`public/topics` 和配置文件之间没有重复事实漂移。
2. 新增字段时，同步更新 [31_数据结构与配置字典](./31_数据结构与配置字典.md)。
3. 新增接口、bridge endpoint、AI 输出字段时，同步更新 [32_API与本地桥接协议](./32_API与本地桥接协议.md)。
4. 新增页面或路由时，同步更新本文档的路由表和 [36_研发任务与需求同步](./36_研发任务与需求同步.md)。
5. 发现 bug 或技术债时，同步更新 [35_缺陷与技术债记录](./35_缺陷与技术债记录.md)。
6. 重大技术取舍记录到 [50_关键决策记录_ADR](../06_决策复盘/50_关键决策记录_ADR.md)。
7. 不要把本地 bridge 或 Codex daemon 当成线上用户能力。
8. 不要直接公开原始 vault；基础公开层允许使用结构化 NK 卡，但必须经过生成清洗、内部痕迹扫描和站点校验。public rewrite 只作为精选层和高风险节点动作。
