本轮专家组一致建议：

```text

近期只接入两类能力：

```

## 2. 专家视角分析

### 2.1 产品战略视角

当前 `book-kb-multi` 的核心不是“再做一个知识库”，而是把用户的真实困境转译成：

- 可以理解的书和概念；
- 可以保存传播的结构卡；
- 可以继续行动的最小路径；
- 可以回流成内容资产的反馈。

因此，外部高星项目给我们的启发应当被压缩成三个产品能力：

| 产品能力 | 对用户的真实价值 | 对应外部样本 |
| --- | --- | --- |
| 结构化表达 | 看一眼知道自己卡在哪里、下一步学什么 | Mermaid、Excalidraw、tldraw |
| 可解释推荐 | 知道为什么推荐这个思想伙伴/书/概念 | Flowise、Dify、n8n |
| 生产流水线 | 让书籍入库、内容生成、发布登记可持续 | n8n、Flowise |

产品判断：先做“可理解、可保存、可复用”的结构图，而不是先做可编辑大画布或完整 RAG 问答。

### 2.2 技术架构视角

当前前端是 Vue + Vite，依赖很克制：`vue`、`d3`、`marked`、`dompurify`、`qrcode`。这意味着：

- 直接接 React 组件库会引入跨框架复杂度；
- 已有 D3 图谱可以继续承担探索型网络图；
- 分享卡 PNG 已经有自绘 canvas fallback，不需要立刻引入重型导出库；
- 最合适的新依赖应当是 ESM、框架无关、能和 Vue 组合。

技术判断：

| 方案 | 技术适配度 | 结论 |
| --- | --- | --- |
| Mermaid | 高 | ESM 包，适合 Vue 中封装成渲染组件 |
| Excalidraw | 中低 | React peer dependency，适合作为参考或独立微应用，不适合直接嵌入当前 Vue 主体 |
| tldraw | 中低 | React SDK，能力强但偏编辑器，当前需求还没到这一步 |
| Flowise | 中 | 不接运行时，学习 ReactFlow 节点/边/导入导出模式 |
| n8n | 中 | 不接运行时，学习 workflow 数据结构、节点类型、连接和 trigger 概念 |

### 2.3 视觉交互视角

我们现在有三种图形表达：

- `KnowledgeGraph.vue`：D3 force graph，适合探索关系；
- `ArticleReader.vue`：canvas 结构画，适合卡片顶部解释；
- `LearningPathMap.vue`：静态路径样张，适合升级成可分享结构图。

外部样本启发：

- Mermaid 适合“结构准确、可由文本生成”的图；
- Excalidraw 适合“手绘感、传播感、低压力理解”；
- tldraw 适合“用户要自己编辑画布”；
- Flowise/n8n 的画布适合“流程透明、节点状态明确”。

视觉判断：近期做 `Mermaid + 自有视觉包裹` 最合适。也就是内部用 Mermaid 保证结构生成，外层仍用我们的排版、色彩和 PNG 导出体系，不把页面变成通用白板。

### 2.4 AI / RAG 工程视角

思想伙伴选配器目前是规则匹配。高星 AI workflow 项目的真正启发是拆分节点，而不是马上引入大模型平台。

建议拆成：

```text
用户困境输入
-> 场景/能力轴识别
-> 候选思想伙伴召回
-> 角色位排序
-> 书籍/概念证据绑定
-> 结果卡生成
-> 行动反馈解释
-> 反馈入库
```

这套结构可以先本地运行，未来如果要接 AI，也只是替换某些节点，而不是推翻整页。

### 2.5 内容运营 / 小红书视角

小红书传播需要“短时间理解 + 保存理由 + 转发理由”。纯图谱太复杂，纯文字又不够有冲击力。

建议优先做两类可传播资产：

1. 学习路径结构图：从一个问题到 3-6 个学习层级。
2. 思想伙伴结果结构图：当前困境、主镜头、行动角色、表达角色、下一步练习。

内容生产流水线可以借 n8n 思路写成节点：

```text
选书 / 选题
-> 结构化知识
-> K/N 卡
-> 图文提示词
-> 可发布正文
-> 发布登记
-> 数据回收
-> 复盘改题
```

### 2.6 安全与维护视角

新增依赖必须谨慎：

- Mermaid 会渲染用户可控文本时，需要使用严格安全配置，并限制输入来源；
- Excalidraw 和 tldraw 都带来 React 依赖和资产/许可/打包复杂度；
- Flowise/n8n 如果作为运行时，会引入账号、服务、数据持久化、权限和部署成本；
- 任何导出图片能力都要继续做桌面/移动端截图验收。

维护判断：先引入 Mermaid 是可控的；暂不引入 Excalidraw/tldraw/Flowise/n8n 运行时。

## 4. 下载切片与研究要点

本地下载位置：

```text

```

已下载切片：

| 项目 | 关键文件 | 看什么 |
| --- | --- | --- |
| Mermaid | `README.md`、`packages/mermaid/package.json`、`packages/mermaid/src/mermaid.ts` | ESM 导出、图表类型、文本转图能力 |
| Excalidraw | `packages/excalidraw/README.md`、`package.json`、browser 示例 | React peer、CSS/容器高度要求、导出 API |
| tldraw | `packages/tldraw/README.md`、导出图片示例、readonly 示例 | SDK 定位、React 接入成本、只读/导出能力 |
| Flowise | canvas 入口、ConversationChain、File loader | ReactFlow 节点/边、画布保存、节点类型定义 |
| n8n | workflow package、manual trigger、workflow 数据结构 | nodes、connections、trigger、workflow class 组织方式 |

关键发现：

- Mermaid 包当前是 ESM，`exports` 指向 `dist/mermaid.core.mjs`，适合 Vite。
- Excalidraw README 明确它作为 React component 导出，并要求引入 CSS、父容器有非零高度。
- tldraw README 明确是 React developers 的 infinite canvas SDK。
- Flowise canvas 使用 ReactFlow，核心是 `nodes/edges`、自定义节点、连接事件、导入 flowData。
- n8n workflow 把 `nodes` 和 `connections` 作为核心数据，并区分 trigger nodes、poll nodes 等。

## 5. 具体实现路径

### 阶段 1：Mermaid 结构图 POC

目标：在不重构页面的前提下，让学习路径地图能渲染一张由文本生成的结构图。

建议任务：

| 任务 | 文件 | 验收 |
| --- | --- | --- |
| 新增 Mermaid 依赖 | `web/package.json` | `npm run build` 通过 |
| 新增 `MermaidDiagram.vue` | `web/src/components/MermaidDiagram.vue` | 输入 Mermaid 文本可渲染 SVG |
| 学习路径数据增加 `diagram` 字段 | `web/src/data/learningPathData.js` | 每条路径至少有一张 flowchart |
| 在 `LearningPathMap.vue` 加结构图区域 | `LearningPathMap.vue` | 桌面/移动端不溢出 |
| 增加安全配置 | `MermaidDiagram.vue` | 使用 strict security，禁用外部不可信 HTML |

建议 Mermaid DSL 示例：

```text
flowchart TD
  A[真实问题] --> B[重新命名卡点]
  B --> C[主书建立框架]
  C --> D[概念节点补盲]
  D --> E[最小练习]
  E --> F[输出一张小红书结构卡]
```

预计成本：0.5-1 天。

### 阶段 2：思想伙伴 workflow schema

目标：把 `ThoughtPartnerTool.vue` 中的匹配逻辑从“组件内部函数”变成可测试的节点式流程。

建议新增：

```text
web/src/features/thought-partner/workflow/
├─ schema.js
├─ runThoughtPartnerWorkflow.js
├─ nodes/
│  ├─ classifyScene.js
│  ├─ scoreAxes.js
│  ├─ rankPartners.js
│  ├─ bindEvidence.js
│  ├─ buildResultCard.js
│  └─ buildFeedbackInsight.js
└─ fixtures/
   └─ defaultScenes.js
```

节点输入输出草案：

| 节点 | 输入 | 输出 |
| --- | --- | --- |
| `classifyScene` | scene、customText | sceneIntent、primaryAxis |
| `scoreAxes` | need、taste、goal | axisScores |
| `rankPartners` | axisScores、scenePreset | rolePartnerSet |
| `bindEvidence` | rolePartnerSet | books、concepts、starterQuestions |
| `buildResultCard` | all previous | resultCardData |
| `buildFeedbackInsight` | feedback、resultCardData | pattern、reading、nextAction、tags |

预计成本：1-2 天。

### 阶段 3：内容生产 pipeline JSON

目标：先用 n8n 的思想，但不引入 n8n 运行时。

建议新增：

```text
04_operations/06_ops_runtime/pipelines/
├─ book_intake_pipeline.json
├─ xhs_release_pipeline.json
└─ README.md
```

pipeline 字段：

```json
{
  "id": "book_intake_to_xhs_posts",
  "nodes": [
    { "id": "source_book", "type": "input", "output": "clean_text" },
    { "id": "structured_knowledge", "type": "llm_extract", "input": "clean_text" },
    { "id": "nk_cards", "type": "card_build", "input": "structured_knowledge" },
    { "id": "xhs_prompt", "type": "prompt_build", "input": "nk_cards" }
  ],
  "edges": [
    ["source_book", "structured_knowledge"],
    ["structured_knowledge", "nk_cards"],
    ["nk_cards", "xhs_prompt"]
  ]
}
```

预计成本：0.5-1 天。

### 阶段 4：结构画导出增强

目标：让 Mermaid 生成的 SVG 能进入现有分享卡/PNG 流程。

路线：

1. 先只页面渲染，不导出。
2. 再做 SVG 下载。
3. 最后把 SVG 画入 canvas 或转成 PNG。

注意：不要先接 Excalidraw/tldraw 的导出能力；当前已有 `ThoughtPartnerTool.vue` 的自绘 canvas，更可控。

预计成本：1-2 天。

### 阶段 5：画布编辑器 POC

只有当出现明确需求时再做：

```text
用户需要自己拖拽、编辑、排布学习路径
或
内部需要可视化编辑思想伙伴 workflow
```

候选：

- Vue Flow：更贴近当前 Vue 技术栈；
- tldraw：更强的无限画布，但 React 和许可成本更高；
- Excalidraw：更适合手绘传播感，但直接嵌 Vue 成本不低。

## 6. 推荐优先级

| 优先级 | 动作 | 原因 |
| --- | --- | --- |
| P0 | Mermaid 学习路径结构图 POC | 最贴近当前“学习路径地图”和小红书结构卡 |

## 7. 风险与边界

| 风险 | 应对 |
| --- | --- |
| 依赖膨胀 | 只先加 Mermaid；其他不进生产依赖 |
| 跨框架成本 | React 类库先不进 Vue 主体 |
| 图太复杂，不适合传播 | 限制结构图节点数量，默认 5-7 个节点 |
| 用户输入图语法导致渲染/安全问题 | 只渲染内部生成的 DSL，配置 strict security |
| 下载样本不完整 | 当前切片足够做分析；全仓库克隆待 GitHub 网络恢复后补 |
