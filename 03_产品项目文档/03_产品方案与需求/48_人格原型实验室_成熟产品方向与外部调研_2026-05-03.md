# 人格原型实验室：成熟产品方向与外部调研

日期：2026-05-03

## 一、结论先行

这个方向可以继续推，而且不应该被定义成“小红书内容工具”或“AI 角色聊天”。更准确的成熟产品定义是：

> 一个以文学原型、真实生命史、家庭/关系脚本和游戏规则为底层材料的人生建模与叙事推演系统。

它的主产品不是发布内容，而是生成、校准和推演“处在真实问题中的人”。小红书、文学趣味号、短剧、小说、分镜、桌游只是这个系统的外显产物。

成熟版必须从现在的静态原型升级为：

```text
本地知识库
-> 文学/心理/游戏源材料抽取
-> 原型内核库
-> 虚拟人生模型
-> 圆桌/规则沙盘推演
-> 内容/故事/游戏输出
-> 用户与专家反馈回流
```

## 二、专家圆桌的综合判断

### 1. 心理动力学评估

人物不应被写成标签，而应写成“保护策略如何形成、如何重复、如何在当下失效”。比如“讨好型人格”太粗；更好的表达是：

```text
早年关系线索 -> 安全交换方式 -> 当前触发场景 -> 保护策略 -> 代价 -> 可练习边界
```

红线：

- 不做心理诊断；
- 不把用户说成“有病”；
- 不把所有问题都归因到童年；
- 不替代心理咨询。

### 2. 家庭系统/萨提亚/鲍恩评估

家庭脚本可以建模，但要避免“父母害了我”的单因果叙事。更适合用系统字段：

- 家庭规则：什么能说、什么不能说。
- 情绪规则：谁可以生气，谁必须懂事。
- 关系位置：谁被期待牺牲，谁被保护，谁被指责。
- 代际愿望：上一代未完成的安全、体面、成功、自由。
- 沟通姿态：讨好、指责、超理智、打岔、一致性表达。

### 3. 文学叙事学评估

文学原型不是“把祥林嫂搬到现代”，而是抽取命运结构：

```text
人物处境 -> 关系结构 -> 社会目光 -> 自我误认 -> 重复事件 -> 命运机制 -> 可移植内核
```

成熟产品里，文学人物要保留出处、版权状态、抽取证据和现代移植边界。

### 4. 游戏设计评估

游戏规则不是装饰，而是“让模式显形”的压力装置。只让 AI 对话不够，必须有状态：

- 玩家资源；
- 可见/隐藏信息；
- 轮次；
- 选择代价；
- 关系值；
- 时间压力；
- 公开评价；
- 事件触发；
- 复盘问题。

### 5. AI 产品/工程评估

成熟版不应只靠长 prompt。推荐结构是：

```text
结构化 JSON/SQLite 知识库
+ 文本向量检索
+ 原型/人物/规则状态机
+ LLM 负责解释、生成和对话
+ 圆桌 Agent 负责多视角校准
```

也就是说，LLM 不是唯一大脑，而是“结构化模型上的推理和表达层”。

### 6. 隐私伦理评估

真实用户建模必须分级：

- 文学原型：可公开展示。
- 虚构用户：可公开展示。
- 匿名用户画像：只展示去标识版本。
- 真实用户生命史：默认本地、私密、可删除。
- 心理敏感字段：默认不进入内容生产链。

## 三、外部应用参考

### 1. AI 角色聊天类

代表：Character.AI、Replika、SillyTavern。

可学：

- 角色卡；
- 长期记忆；
- 世界书/lorebook；
- 多角色群聊；
- 人设和语气管理。

局限：

- 容易停留在角色扮演；
- 缺少严肃的生命史和证据链；
- 对“规则推演”和“内容回流”的支持弱。

参考：

- [Character.AI](https://character.ai/)
- [Replika memory documentation](https://help.replika.com/hc/en-us/articles/37208679176077-How-does-Replika-s-memory-work)
- [SillyTavern Documentation](https://docs.sillytavern.app/)

### 2. 写作/世界观管理类

代表：World Anvil、Campfire、Notion 写作库、Obsidian 知识库。

可学：

- 角色小传；
- 世界观设定；
- 时间线；
- 场景库；
- 关系网；
- 创作素材管理。

局限：

- 更偏创作者资料库，不直接模拟真实用户成长。
- 缺少心理机制、家庭脚本和游戏规则层。

参考：

- [World Anvil](https://www.worldanvil.com/)
- [Twine](https://twinery.org/)

### 3. 互动叙事/游戏创作类

代表：Twine、Ink、Ren'Py、ChoiceScript。

可学：

- 状态变量；
- 分支剧情；
- 选择代价；
- 条件触发；
- 可回放互动故事。

局限：

- 人物深度需要作者手写。
- 与心理/文学/内容知识库天然不打通。

## 四、前沿论文与技术线索

### 1. Generative Agents

Stanford/Google 的 Generative Agents 提出用记忆、反思和计划模拟可信人类行为。它对本项目最重要的启发是：虚拟人不能只有人设，还要有记忆流、反思机制和行动计划。

参考：

- [Generative Agents: Interactive Simulacra of Human Behavior](https://arxiv.org/abs/2304.03442)
- [GitHub: joonspk-research/generative_agents](https://github.com/joonspk-research/generative_agents)

### 2. Concordia

DeepMind 的 Concordia 是面向生成式社会模拟的库，核心思想是把角色、环境、规则、记忆、度量拆成组件。它非常适合参考“人生沙盘”的技术架构。

参考：

- [GitHub: google-deepmind/concordia](https://github.com/google-deepmind/concordia)

### 3. SOTOPIA

SOTOPIA 关注开放式社交智能评估，让 Agent 在社会场景中互动，并评估目标完成、关系、规则等。它适合用来参考圆桌和人生场景的评估方式。

参考：

- [SOTOPIA paper](https://arxiv.org/abs/2310.11667)
- [GitHub: sotopia-lab/sotopia](https://github.com/sotopia-lab/sotopia)

### 4. BookWorld

BookWorld 的方向和本项目特别接近：从小说构建互动 Agent 社会。它说明“从文学文本抽取角色、场景、社会关系，再生成可互动世界”已经是一个明确前沿方向。

参考：

- [BookWorld: From Novels to Interactive Agent Societies for Creative Story Generation](https://arxiv.org/abs/2504.14538)

### 5. Open-Theatre / IBSEN

这类系统关注 LLM 驱动的交互戏剧、导演-演员协作、角色记忆和剧情推进。对本项目的启发是：需要一个“导演层”来控制节奏，而不是任由角色聊天发散。

参考：

- [OPEN-THEATRE: An Open-Source Toolkit for LLM-based Interactive Drama](https://arxiv.org/abs/2509.16713)
- [GitHub: johnnie193/Open-Theatre](https://github.com/johnnie193/Open-Theatre)
- [IBSEN: Director-Actor Agent Collaboration for Controllable and Interactive Drama Script Generation](https://arxiv.org/abs/2407.01093)

### 6. Story2Game

Story2Game 强调把故事转成可玩的互动游戏，关键在于把剧情拆成状态、前置条件、行动和结果。对本项目的启发是：人格原型要进入游戏，必须先变成状态机。

参考：

- [STORY2GAME: Generating (Almost) Everything in an Interactive Fiction Game](https://arxiv.org/abs/2505.03547)

### 7. 叙事身份与文学社会模拟

叙事身份研究支持“人通过生命故事理解自己”的底层假设；文学作为社会经验模拟支持“小说人物可以作为人性原型库”的方向。

参考：

- [McAdams: Narrative Identity](https://journals.sagepub.com/doi/10.1177/0276236618756704)
- [Oatley & Mar: Fiction as Simulation of Social Experience](https://journals.sagepub.com/doi/10.1111/j.1745-6924.2008.00073.x)

## 七、知识库对象设计

成熟版至少需要 7 类对象：

### 1. SourceWork 源作品

记录一本书、一篇小说、一个剧本、一个游戏机制来源。

字段：

- `id`
- `title`
- `author`
- `source_type`
- `local_path`
- `copyright_status`
- `usable_scope`
- `themes`
- `ingestion_status`

### 2. ArchetypeKernel 原型内核

从作品中抽取的人格/命运结构。

字段：

- `id`
- `title`
- `source_work_ids`
- `core_situation`
- `need`
- `fear`
- `protection_strategy`
- `relationship_script`
- `family_script`
- `social_gaze`
- `language_style`
- `destiny_pattern`
- `modern_transplants`
- `evidence_refs`

### 3. VirtualPerson 虚拟人生

一个可进入圆桌和游戏沙盘的人。

字段：

- `id`
- `name`
- `fictional_level`
- `source_archetype_ids`
- `life_stage`
- `current_problem`
- `life_timeline`
- `family_system`
- `relationship_patterns`
- `self_narrative`
- `protection_strategies`
- `triggers`
- `growth_edges`
- `privacy_level`
- `evidence_refs`

### 4. LifeScene 人生场景

现代处境，如家庭群、婚恋冲突、职场复盘、内容数据焦虑。

字段：

- `id`
- `title`
- `domain`
- `roles`
- `pressure`
- `conflict_path`
- `signals`
- `possible_actions`
- `content_angles`

### 5. RuleSet 游戏规则

让模式显形的互动规则。

字段：

- `id`
- `title`
- `state_variables`
- `visible_information`
- `hidden_information`
- `actions`
- `costs`
- `turn_structure`
- `win_or_progress_condition`
- `review_prompts`

### 6. RoundtableSession 圆桌会话

一次真实或模拟推演。

字段：

- `id`
- `virtual_person_id`
- `problem_case_id`
- `archetype_kernel_ids`
- `rule_set_ids`
- `agent_turns`
- `insights`
- `action_card`
- `content_artifacts`

### 7. OutputArtifact 输出物

小红书、文学号、短剧、小说、游戏样张。

字段：

- `id`
- `source_session_id`
- `artifact_type`
- `title`
- `outline`
- `visual_prompt`
- `script`
- `publish_channel`
- `review_status`

## 九、哪些可以直接生成，哪些必须等输入

### 可以直接生成

基于常识、公共领域知识和本地已有书籍索引，可以直接生成：

- 4-20 个通用人格原型；
- 20-50 个现代生活场景；
- 10-20 个游戏规则机制；
- 圆桌角色分工；
- 内容选题；
- 虚构用户样张。

但这些只能标为“创作型原型”或“启发型假设”。

### 必须输入作品后才能生成

以下不能空口生成成熟版本：

- 某部小说的准确人物原型；
- 文本证据链；
- 具体语言风格；
- 人物关系网；
- 章节级命运结构；
- 可公开引用的摘录。

### 必须用户授权后才能生成

以下需要真实用户材料和明确授权：

- 真实用户生命史模型；
- 原生家庭多代传承线；
- 婚恋/亲密关系脚本；
- 可进入内容链的匿名案例；
- 任何可能识别真实人的素材。

## 十、人物构建能不能足够细节和真实

可以，但要分三层成熟度。

### L1：文学原型人物

来源：文学作品 + 叙事抽取。

真实感来自：

- 关系结构；
- 命运模式；
- 语言风格；
- 社会目光；
- 关键场景。

适合内容和创作，不适合当成真实用户。

### L2：虚构复合用户

来源：多个原型 + 现代场景 + 心理机制。

真实感来自：

- 一致的生命史；
- 可重复的行为模式；
- 具体触发场景；
- 自我叙事；
- 保护策略；
- 成长边界。

适合圆桌、内容、游戏原型。

### L3：授权真实用户模型

来源：用户访谈 + 本地材料 + 用户反复校正。

真实感来自：

- 真实事件；
- 用户自己的语言；
- 时间线；
- 家庭/关系事实；
- 反馈校正；
- 行动复盘。

这层最有价值，也最需要伦理保护。

## 十一、和圆桌如何打通

圆桌不应该再拥有独立的虚拟用户数据。成熟版应该是：

```text
ArchetypeLab 负责生产/编辑 ArchetypeKernel、LifeScene、RuleSet
VirtualPersonBuilder 负责把它们组合成 VirtualPerson
Roundtable 读取 VirtualPerson + ProblemCase + EvidenceRefs
ContentOps 读取 RoundtableSession 生成内容
```

统一数据关系：

```text
SourceWork
  -> ArchetypeKernel
  -> VirtualPerson
  -> RoundtableSession
  -> OutputArtifact

LifeScene + RuleSet 可以同时被 ArchetypeLab 和 Roundtable 调用。
```

这意味着：

- `/tools/archetype-lab` 是原型生成和调试器；
- `/tools/roundtable` 是人物进入问题后的多智能体推演器；
- `/tools/content-ops` 是输出物管理器；
- `/tools/space-browser` 未来可以展示这些对象的空间地图。

任务：

- 每个原型必须有来源、证据、关系结构、现代移植；

- 输出可用于文学趣味号的选题。

### P2：虚拟人生生成器

目标：从原型 + 场景 + 规则生成可进入圆桌的人。

任务：

- 生成生命时间线；
- 生成家庭脚本；
- 生成亲密关系脚本；
