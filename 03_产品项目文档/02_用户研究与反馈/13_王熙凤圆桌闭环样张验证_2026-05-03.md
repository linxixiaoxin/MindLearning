## 1. 输入样张

原始处境：

```text
预算突然被砍，项目需要救火，领导第一反应是让我来盯，团队第一反应是等我拍板。
我能把事情压住，但大家越来越不敢自己判断，我也越来越累。
```

内容原型：

```text
王熙凤不是“控制狂女领导”的标签。
她显影的是：复杂组织如何把一个能人推成控制中枢。
```

## 2. 结构化沉淀

本轮新增 5 个知识库对象：

| 类型 | ID | 用途 |
| --- | --- | --- |
| `ArchetypeKernel` | `wangxifeng-control-hub` | 把自己活成系统控制中枢的人 |
| `VirtualPerson` | `wangxifeng-office-lead` | 可进入圆桌的凤姐式项目骨干 |
| `LifeScene` | `wangxifeng-budget-cut-meeting` | 预算被砍后的项目复盘会 |
| `RuleSet` | `single-point-dependency` | 单点依赖与授权不清 |
| `RoundtableSession` | `roundtable-session-wangxifeng-control-hub-2026-05-03` | 一次完整圆桌样张 |

## 3. 圆桌跑出的核心结论

问题命名：

```text
真正卡住的不是她个人太强，而是组织把混乱、风险和决策不断接到同一个能人身上，让她既获得安全感，也承担过载。
```

隐含假设：

```text
如果我不盯，局面就会塌。
如果别人做不好，最后还是我背锅。
只有我压住全局，我的位置才安全。
```

最小行动：

```text
本周选择一个低风险流程，把标准、风险和拍板边界写清，让一位同事先接一段；
你只同步风险，不立刻收回全部拍板权。
```

成功信号：

```text
团队至少有一个人能在不等你点头的情况下推进一小步。
```

## 4. 内容回流样张

回流标题：

```text
别把一个能人，用成整个系统的补丁
```

可进入小红书的 6 页图文链：

```text
1. 预算突然被砍，所有人都看向那个最能扛事的人。
2. 她能救火，也让团队越来越不敢自己判断。
3. 真正的问题不是能力强，而是秩序被绑在她一个人身上。
4. 互动循环：混乱出现 -> 她接管 -> 效率上升 -> 团队后退 -> 她更不敢放手。
5. 同事动作：把进度、风险、选项和权限边界摆出来。
6. 领导动作：别只用她救火，把她的经验写成流程并培养替手。
```

可测试评论引导：

```text
你身边有没有那种“很能干，但所有人都等她一句话”的人？
你觉得这种局面更像个人性格问题，还是组织把她推到了那个位置？
```

## 5. 网站演示入口

现在网站端不是后台自动“生成一轮”，而是先把 KB 里已经沉淀好的样张读取出来，再在圆桌页面做可视化重放。

可看的位置：

- `/tools/roundtable/`：顶部点击 `播放王熙凤样张`，页面会从“问题进入”开始，自动推进到“内容回流”。
- 右侧 `会话沉淀`：能看到 `roundtable-session-wangxifeng-control-hub-2026-05-03` 这条 KB 样张；`恢复` 是静态复原，`播放` 是从第一阶段重放。
- `/tools/content-ops/`：`圆桌回流池` 会读取同一条 Roundtable Session 的内容素材，用来承接后续选题、图文链和评审。

这次补充后的玩法理解：

```text
JSON 是后台沉淀层；
圆桌页面是互动 / 演示层；
会话沉淀是互动记录入口；
内容运营页是结果回流入口。
```

## 6. 产品验证结论

通过项：

| 验证点 | 结论 |
| --- | --- |
| 内容样张能否沉淀成原型对象 | 可以，且字段较完整 |
| 圆桌是否能给出非诊断式解释 | 可以，核心表达保持为“假设/线索/组织机制” |
| 是否能回流到内容运营 | 可以，已生成 `ContentArtifact` 结构 |
| 是否保留文学复杂性 | 基本保留，没有把王熙凤简化成坏人标签 |
| 网站端是否能看懂样张如何流动 | 已补演示播放入口，能看到阶段切换、角色焦点和会话记录 |

暴露问题：

| 问题 | 后续动作 |
| --- | --- |
| ProblemCase 已新增但还需验证入口命中 | 用更多王熙凤式原始问题测试 `control-hub-dependency` 的召回 |
| 《红楼梦》文本证据还不够具体 | 补具体章回、场景和人物关系证据 |
| KB 样张还没有筛选和评审入口 | 为 `/tools/roundtable` 和 `/tools/content-ops` 增加样张筛选、搜索、评审状态 |
| 专家评审还没进入流程 | 至少补文学研究、组织行为、心理边界三类评审 |

## 7. 下一步

建议下一轮只做一件事：

```text
用 3-5 条不同口吻的王熙凤式原始问题，测试 `control-hub-dependency` 的入口命中、圆桌输出和内容回流质量。
```

这会比继续扩原型数量更重要，因为它能验证：圆桌不是只会套单一样张，而是真的能接住文学人物带来的新组织机制。
