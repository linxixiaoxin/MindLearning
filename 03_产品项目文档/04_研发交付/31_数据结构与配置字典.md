> 创建时间：2026-04-29

## 1. 维护原则

当前阶段优先使用前端静态配置和 JSON 文件，避免过早建设后台。

字段设计原则：

- 能解释推荐逻辑。
- 能支持保存图片和分享卡。
- 能支持后续接专题页、书籍节点和 N/K 卡。
- 能支持 AI / Codex 交接。
- 不收集不必要的用户身份信息。

## 2. 公开书籍发布分层

ADR-007 后，扩容书籍不再只有“灰度 / 正式”两种状态，而是按公开层级判断。

建议在构建配置或 manifest 中使用：

```json
{
  "publication": {
    "layer": "public_structured_nk",
    "curationStatus": "needs_curated_overrides",
    "sourceVisibility": "private_source",
    "generatedFrom": ["structured_json", "kn_table"],
    "overrideDir": "configs/public_overrides/<slug>",
    "publicSanity": {
      "status": "pass",
      "blockerCount": 0,
      "samples": []
    }
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `publication.layer` | string | 公开层级，建议值：`gray_candidate`、`public_structured_nk`、`public_curated`、`private_source` |
| `curationStatus` | string | 精修状态，建议值：`not_started`、`needs_curated_overrides`、`needs_source_repair`、`partially_curated`、`curated` |
| `sourceVisibility` | string | 源资产可见性，默认 `private_source` |
| `generatedFrom` | array | 生成依据，如 `structured_json`、`kn_table`、`summary_md` |
| `overrideDir` | string | 人工精修覆盖稿目录，只存放少量精选卡覆盖稿 |
| `publicSanity.status` | string | 公开面卫生状态，建议值：`pass`、`needs_source_repair` |
| `publicSanity.blockerCount` | number | 公开面命中的 OCR、书单污染、字段错配等风险数量 |
| `publicSanity.samples` | array | 公开面风险样例，供回源修复使用，不作为前台展示文案 |

约束：

- `web/public/books/<slug>` 是生成产物，不作为手工内容事实源。
- `web/public/registry/books.json` 应由构建生成或校验同步，不再长期手工维护。
- `01_sources/01_books/**` 保留为本地源资产，不直接进入公开阅读器。
- public rewrite 不再是整本书上线前置，只用于精选层、高风险节点和外部传播入口。
- `needs_source_repair` 不等于下架；它表示基础公开层可访问，但源结构化资产需要回源校准，不能进入“精选公开”判断。

## 3. 困境配置

建议结构：

```js
{
  id: "S01",
  title: "刷完小红书更讨厌自己的生活",
  primaryAxis: "seeing",
  secondaryAxes: ["social", "inner"],
  restatement: "...",
  lens: "...",
  defaultAction: "...",
  explorePaths: []
}
```

字段说明：

| 字段 | 类型 | 说明 | 必填 |
| --- | --- | --- | --- |
| `id` | string | 困境编号 | 是 |
| `title` | string | 用户可见困境标题 | 是 |
| `primaryAxis` | string | 主能力轴 | 是 |
| `secondaryAxes` | array | 辅助能力轴 | 是 |
| `restatement` | string | 困境重述 | 是 |
| `lens` | string | 学科母题镜头 | 建议 |
| `defaultAction` | string | 默认最小行动 | 是 |
| `explorePaths` | array | 继续探索路径 | 建议 |

## 5. 思想伙伴配置

建议结构：

```js
{
  id: "bachelard",
  name: "巴什拉",
  source: "空间的诗学",
  axes: ["seeing", "inner"],
  roles: ["mainLens", "expressionPartner"],
  tones: ["poetic"],
  fitReason: "...",
  avoidWhen: "...",
  links: []
}
```

字段说明：

| 字段 | 类型 | 说明 | 必填 |
| --- | --- | --- | --- |
| `id` | string | 内部标识 | 是 |
| `name` | string | 作者、思想或方法名 | 是 |
| `source` | string | 来源书籍或方法 | 建议 |
| `axes` | array | 适配能力轴 | 是 |
| `roles` | array | 可担任的伙伴角色 | 是 |
| `tones` | array | 表达气质标签 | 建议 |
| `fitReason` | string | 推荐理由 | 建议 |
| `avoidWhen` | string | 不适用边界 | 可选 |
| `links` | array | 相关专题/书籍/N卡 | 建议 |

## 12. 数据质量检查

每次改配置时检查：

- 所有困境都有主轴和最小行动。
- 所有角色都能匹配到伙伴。
- 所有用户可见文案无内部字段名泄露。
- `explorePaths` 不出现死链。
- Codex JSON 返回字段能被页面解析。
- 保存图片使用的字段不为空。
