# 语言—视角—模式—情绪—需求：产品结构图

> 结构用途：解释为什么这条母题是 `book-kb-multi` 的底层世界观，而不是一条普通功能线。
> 关联文档：`06_产品重定义_问题驱动思想工作台_2026-04-30.md`、`28_语言视角模式情绪需求统一母题.md`、`20_PRD_思想伙伴选配器.md`、`22_用户流程与交互说明.md`、`23_内容与推荐规则说明.md`

## 1. 总图

```text
真实场景 / 原话 / 热点 / 书页
        ↓
      语言
        ↓
      视角
        ↓
      模式
        ↓
      触发
        ↓
      情绪
        ↓
      需求
        ↓
   表达 / 行动 / 内容 / 学习
```

这不是线性流水账，而是一层层“解释权”的递进：

- 语言决定事情怎么被说出来。
- 视角决定事情被看成什么。
- 模式决定事情会不会自动重复。
- 触发决定旧反应何时启动。
- 情绪决定哪里被碰到了。
- 需求决定真正缺什么。
- 表达 / 行动决定最后怎么改。

## 2. 四个入口视角

### 2.1 从语言进入

输入一段原话、标题、评论、对话。

系统要问：

- 这句话用了什么词？
- 它预设了什么解释？
- 它把谁放在了什么位置？
- 它正在激活哪种模式？

### 2.2 从视角进入

输入一个冲突、分歧、困惑或社会事件。

系统要问：

- 不同心智层级会怎么看它？
- 不同角色会看见什么、忽略什么？
- 哪种解释框架在主导这件事？

### 2.3 从情绪进入

输入恐惧、愤怒、委屈、低落、兴奋、迷茫。

系统要问：

- 这个情绪背后可能是哪种需要？
- 它是被哪句原话、哪个场景、哪个关系位置触发的？
- 它对应的是安全感、边界、被理解，还是被看见？

### 2.4 从模式进入

输入重复出现的困境。

系统要问：

- 它反复出现在哪些场景？
- 它的触发器是什么？
- 它的旧反应路径是什么？
- 它和哪些信念绑定在一起？

## 3. 产品层的三条主线

### 3.1 问题工作台：拆 A / B / C

- A：事件 / 别人的话 / 场景
- B：想法 / 信念 / 模式
- C：情绪 / 行为

问题工作台的职责不是下诊断，而是把原话拆成可看的结构。

### 3.2 思想伙伴选配器：多视角解释

思想伙伴不是“答题器”，而是“视角集合”。

它负责：

- 用不同作者的语言看同一个问题
- 让不同学派的解释并排出现
- 用角色差异来暴露用户视角盲区

### 3.3 选题中台：把需求翻成内容

内容不是从概念开始，而是从需求开始：

- 情绪信号
- 真实场景
- 被卡住的需要
- 可以命名的痛点
- 能写成一篇内容的切口

## 4. 这条结构图对应的学科支撑

- 语言学：语言并不是中性容器，而是组织经验的方式。
- 认知心理学：人会用解释框架和信念系统过滤同一事件。
- 发展心理学 / 成人发展：不同心智层级有不同的世界解释方式。
- 认知行为疗法：A 不是直接生成 C，中间有 B。
- 情绪研究：情绪是需要与关系状态的信号。
- 社会学 / 传播学：场景、角色、话语和舆论会塑造解释。
- 营销学 / 内容策略：真正的内容切口往往来自需求，而不是概念本身。

## 5. 为什么它是底层，而不是一个功能点

因为它解释的是“人怎么把世界变成可理解、可反应、可表达的东西”。

这比某个单独页面更底层：

- 它能统一问题工作台。
- 它能统一思想伙伴。
- 它能统一情绪坐标。
- 它能统一学习路径。
- 它也能统一小红书内容生产。

所以它更像整个产品的**世界观层**，不是某个模块的小技巧。
