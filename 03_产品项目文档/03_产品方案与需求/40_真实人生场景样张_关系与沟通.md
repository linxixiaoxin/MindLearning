# 场景样张：关系与沟通

> 状态：v0.2 结构化样张
> 关联主线：`真实人生场景入口与人生沙盘模拟`
> 关联模块：`Problem Case`、`思想伙伴选配器`、`学习路径地图`、`能力路径`、`选题中台`

## 1. 本样张要验证什么

验证用户是否愿意从“关系冲突表面”进入“需求与边界”的分析入口。

核心假设：

- 用户真正卡住的往往不是道理，而是触发；
- 同一句话，不同人听见的是不同视角；
- 很多关系问题其实是安全感、边界和需要没有被看见；
- 用户愿意先看结构，再做表达和修复。

## 2. 页面目标

让用户在这个入口里看到：

- 这句话为什么会触发我；
- 我在意的到底是什么；
- 对方看见的是什么；
- 我真正缺的是什么；
- 下一步怎样重述或修复。

## 3. 页面结构

### 3.1 顶部

- 标题：关系与沟通
- 一句话说明：先看触发，再看需要
- 输入：原话 / 冲突 / 场景描述

### 3.2 中部

- 原话分析
- 触发词高亮
- 视角差异
- 模式识别
- 需求推测

### 3.3 下方

- 推荐 Problem Case
- 推荐思想伙伴
- 推荐学习路径
- 推荐能力路径
- 最小行动

## 4. 这个样张的产品表达

### 4.1 不急着评判对错

这个入口要避免直接把关系问题做成：

- 谁对谁错；
- 谁有问题；
- 该不该分开。

而是先回到结构：

- 语言；
- 视角；
- 模式；
- 情绪；
- 需要；
- 边界。

### 4.2 把关系问题看成可修复的结构

系统的作用不是替用户吵赢，
而是帮助他看见：

- 触发点在哪里；
- 需求在哪一层没被看见；
- 怎么换一种表达方式。

## 5. 进入 Problem Case 的方式

可以把这个场景转成如下问题：

- 为什么这句话让我这么难受？
- 对方可能听到了什么？
- 我真正想要的是什么？
- 我的边界在哪里？

## 6. 最小行动

建议样张输出一个最小行动：

- 写出 1 句事实；
- 写出 1 句感受；
- 写出 1 个请求；
- 或者写出 1 个边界表达。

## 7. 验收标准

- 用户能从冲突表面走向结构理解；
- 用户能看见自己的触发和需要；
- 页面能引导到 Problem Case；
- 页面能引导到学习路径和能力路径；
- 不把关系问题做成玄学或道德裁判。

## 8. 场景卡样例

| 字段 | 内容 |

| 场景 ID | `relationship-communication` |
| 场景名称 | 关系与沟通 |

## 9. 页面样张结构

### 9.1 首屏

```text
关系与沟通
先看触发，再看需要。

[粘贴一句原话 / 描述一个冲突]
[我不想写细节，先从常见触发开始]

你可以先分析：
- 这句话触发了什么
- 我听到了什么
- 对方可能想表达什么
- 我的需要和边界在哪里
- 下一句怎么说更不伤人也不委屈自己
```

首屏需要让用户感觉这里不是评判台，而是一个把关系拆开看的工作台。

### 9.2 中部地图

| 地图区块 | 展示内容 | 目的 |
| --- | --- | --- |
| 原话层 | 对方说了什么，用户听到了什么 | 区分事实和解释 |
| 触发层 | 哪些词或语气引发反应 | 找到情绪入口 |
| 视角层 | 我方视角、对方视角、旁观视角 | 减少单一叙事 |
| 模式层 | 讨好、回避、控制、指责、沉默等 | 看见重复模式 |
| 需要层 | 被理解、被尊重、安全感、空间、合作 | 把情绪翻译成需要 |
| 表达层 | 事实、感受、请求、边界 | 给出可执行话术 |

### 9.3 承接区

| 承接区 | 内容 |
| --- | --- |
| 当前问题命名 | “你卡住的不是这一句话，而是这句话触发了旧模式。” |
| 推荐 Problem Case | 触发理解、视角差异、真实需要、边界表达、修复对话 |
| 推荐思想伙伴 | 非暴力沟通、关键对话、家庭系统、成人发展视角 |
| 推荐学习路径 | 事实/故事拆分、需求表达、边界练习、复盘 |
| 推荐行动 | 写 1 句事实、1 句感受、1 个请求或 1 个边界 |

## 10. 关系结构地图样例

| 维度 | 需要回答的问题 | 常见误区 | 系统提示 |
| --- | --- | --- | --- |
| 事实 | 对方具体说了什么、做了什么？ | 把解释当事实 | 先只写可被摄像机拍到的部分 |
| 故事 | 我给这件事加了什么解释？ | “他就是不在乎我” | 把解释写成假设，而不是结论 |
| 情绪 | 我当下最强的感受是什么？ | 用愤怒遮住害怕和委屈 | 允许多种情绪同时存在 |
| 需要 | 这份情绪指向什么需要？ | 只想证明自己对 | 翻译成被理解、尊重、支持、空间 |
| 边界 | 什么是我不能接受的？ | 把边界说成威胁 | 边界是说明自己的限制和选择 |
| 修复 | 下一句怎么说？ | 解释太多或攻击对方 | 用事实、感受、请求收束 |

## 11. Problem Case 映射

| Problem Case | 用户原话 | 适合输出 |
| --- | --- | --- |
| `relationship-trigger` | “为什么这句话让我这么难受？” | 触发词、情绪、旧模式识别 |
| `relationship-perspective-gap` | “对方为什么完全不懂我？” | 视角差异、误听路径、重述练习 |
| `relationship-need` | “我到底想要什么？” | 需要翻译、请求表达 |
| `relationship-boundary` | “我该怎么表达边界？” | 边界句式、风险提示 |
| `relationship-repair` | “现在还能怎么修复？” | 对话重启、承认/澄清/请求模板 |

## 12. 轻量沙盘推演样例

| 路径 | 短期收益 | 中期影响 | 隐藏成本 | 复盘问题 |
| --- | --- | --- | --- | --- |
| 立刻反击 | 能快速释放委屈 | 冲突升级概率高 | 对方更难听见真正需要 | 我真正想让对方听见什么？ |
| 压下不说 | 避免当下冲突 | 问题可能继续累积 | 自己的需要被长期忽略 | 如果不说，我会付出什么代价？ |
| 先写事实和感受 | 降低表达混乱 | 更容易进入修复对话 | 需要短暂停顿和自我觉察 | 事实和故事分别是什么？ |
| 直接表达边界 | 保护自己的底线 | 关系会进入重新协商 | 如果语气太硬，可能被听成攻击 | 我的边界是限制自己，还是惩罚对方？ |

## 13. 表达重写模板

第一版可以提供一个轻量模板，不必生成长篇咨询建议。

```text
事实：当你说 / 做了 ________，
感受：我感到 ________，
解释：我脑子里冒出来的故事是 ________，
需要：我其实需要 ________，
请求：你是否愿意 ________？
边界：如果接下来还是 ________，我会先 ________。
```

关系场景的最小行动可以只要求用户完成其中 3 格，而不是一次写完全部。

## 15. 内容切口

| 切口 | 标题方向 |
| --- | --- |
| 触发 | 一句话让你崩溃，通常不是因为这句话本身 |
| 事实与故事 | 关系沟通第一步：先分清事实和脑补 |
| 边界 | 边界不是威胁对方，而是说明我会如何保护自己 |
| 需要 | 你以为你想赢，其实你想被看见 |
| 修复 | 吵完以后，真正有用的是这 3 句重启对话 |

## 16. 第一版验收补充

这张样张做到 `Ready` 的标准：

- 有完整 `LifeScene` 场景卡；
- 有原话、触发、情绪、需要、边界结构；
- 有 4 个以上 Problem Case 入口；
- 有至少 3 条沟通沙盘路径；
- 有明确“不做道德裁判 / 不替用户吵赢”的边界；
- 有一个可立刻使用的表达重写模板。

高风险边界需要单独提示：如果场景涉及暴力、威胁、持续控制或人身安全，系统不做普通沟通建议，应提示优先寻求现实支持和专业帮助。
