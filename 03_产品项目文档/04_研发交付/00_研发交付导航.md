## 1. 这个目录负责什么

`04_研发交付/` 是研发侧的主工作台，不再只是“技术资料堆放处”。它负责把产品需求转换成可开发、可验证、可发布、可回滚的工程材料。

当前研发文档分成 6 层：

| --- | --- | --- |
| 研发入口 | 我现在应该先看什么 | 本文档 |

## 2. 开发时的阅读顺序

### 2.1 接新需求

1. 先看产品需求是否已进入 [24_版本需求池与优先级](../03_产品方案与需求/24_版本需求池与优先级.md)。
2. 再看本目录的 [36_研发任务与需求同步](./36_研发任务与需求同步.md)，确认是否已有 DEV 任务。
3. 涉及数据字段，更新 [31_数据结构与配置字典](./31_数据结构与配置字典.md)。
4. 涉及接口、AI、bridge、inbox，更新 [32_API与本地桥接协议](./32_API与本地桥接协议.md)。
5. 涉及架构取舍，补到 [50_关键决策记录_ADR](../06_决策复盘/50_关键决策记录_ADR.md)。

### 2.2 改代码前

1. 读 [30_技术架构说明](./30_技术架构说明.md)，确认目标文件属于哪一层。
2. 查 [35_缺陷与技术债记录](./35_缺陷与技术债记录.md)，避免重复修同一个问题。
3. 查 [33_测试计划与验收用例](./33_测试计划与验收用例.md)，确认改完要跑什么。
4. 如果是发布相关修改，再查 [34_发布与回滚清单](./34_发布与回滚清单.md)。

### 2.3 做内容扩容

1. 先看 [44_50本灰度接入清单与转写分层_2026-04-30](./44_50本灰度接入清单与转写分层_2026-04-30.md)。
2. 再看 [45_5本public_entry样张_2026-04-30](./45_5本public_entry样张_2026-04-30.md)。
3. 正式接入看 [46_5本全量NK卡正式接入记录_2026-04-30](./46_5本全量NK卡正式接入记录_2026-04-30.md) 和 [47_19本对齐心智误区与意识进化结构标准_2026-04-30](./47_19本对齐心智误区与意识进化结构标准_2026-04-30.md)。
4. 改脚本前先看项目根目录 `scripts/` 和 `web/scripts/`，不要手写重复流水线。

### 2.4 做视觉、图谱、3D 或开源工具学习

1. 先看 [39_GitHub先进框架与视觉工具调研_2026-04-30](./39_GitHub先进框架与视觉工具调研_2026-04-30.md)。
2. 再看 [42_GitHub热门应用学习分析/00_索引](./42_GitHub热门应用学习分析/00_索引.md)。
3. 涉及 3D 书籍地图，看 [40_大型3D书籍地图重构调研与素材方案_2026-05-02](./40_大型3D书籍地图重构调研与素材方案_2026-05-02.md)。

## 3. 当前工程分层

```text
RedBook workspace
└─ 04_operations/04_products_and_experiments/book-kb-multi/
   ├─ configs/                         # 书籍配置、扩容候选、公开入口稿
   ├─ scripts/                         # 内容扩容、发布校验、知识库导出等项目级脚本
   ├─ web/
   │  ├─ src/                           # Vue 前端应用
   │  ├─ public/                        # 静态站点数据、书籍包、专题、资产
   │  ├─ scripts/                       # 站点校验、本地 bridge、agent daemon、3D 资产脚本
   │  ├─ netlify/functions/             # 线上 AI 洞察接口
   │  └─ codex-inbox/                   # 本地 Codex 半自动交接文件
   └─ 03_产品项目文档/
      └─ 04_研发交付/                  # 本目录
```

工程当前不是传统后端应用，而是“静态内容产品 + 前端工具实验 + 本地研发 bridge”的组合：

```text
本地书籍/结构化知识资产
-> configs 与生成脚本
-> web/public 静态产物
-> Vue 前端读取 registry/book/topic/tool 数据
-> Netlify 静态部署
-> 可选：Netlify Function 生成 AI 洞察
-> 可选：本地 Codex bridge 做内部协作
```
