# 3D 地球书库技术实现方案

> 版本：v0.1
> 目标：先做网页端 MVP，再决定是否 App 化

## 1. 推荐技术路线

### 首选

- 前端：Vue 3 或 React
- 3D：Three.js 或 React Three Fiber
- 动画：GSAP / Tween.js
- 数据：本地 JSON + 后续 API

### 为什么先这样做

- 网页端最容易快速验证
- 分享和传播成本低
- 能先跑通“探索 -> 点击 -> 详情”的主链路
- 后面如果成立，再迁移到 Flutter / 原生 / Unity 都不晚

## 2. 技术架构

```mermaid
flowchart LR
    A[内容数据 JSON/API] --> B[点位映射层]
    B --> C[3D 场景层]
    C --> D[相机与交互层]
    D --> E[命中检测 / Raycast]
    E --> F[信息卡]
    F --> G[详情页 / 书页 / 专题页]
```

## 3. 关键模块

### 3.1 数据层

负责把书、主题、地点、作者整理成统一结构：

```json
{
  "id": "xxx",
  "type": "book",
  "title": "...",
  "subtitle": "...",
  "lat": 0,
  "lng": 0,
  "tags": [],
  "cover": "...",
  "targetUrl": "/books/..."
}
```

### 3.2 场景层

负责：

- 创建球体
- 创建点位
- 控制相机
- 调整缩放与旋转
- 处理响应式大小

### 3.3 交互层

负责：

- 拖动旋转
- 滚轮缩放
- 点击命中测试
- 高亮当前选中点位
- 打开信息卡

### 3.4 承接层

负责把 3D 场景里的内容转到现有内容页：

- 书页
- 专题页
- 学习路径页
- 其他相关主题页

## 4. MVP 要求

### 必须有

- 1 个主场景
- 20-50 个点位
- 可旋转
- 可缩放
- 可点击
- 信息卡
- 跳转详情

### 暂不做

- 大规模实时三维资源加载
- 复杂物理模拟
- 用户自定义编辑器
- 多层世界嵌套编辑

## 5. 性能与降级

### 性能策略

- 点位不要无限增长
- 按主题分簇，缩放后再展开
- 移动端减少特效与透明层
- 低端设备可以切到 2D 地图或列表模式

### 降级策略

如果 3D 不可用：

- 显示列表版世界地图
- 保留筛选、搜索、详情跳转
- 不让入口完全失效

## 6. 与现有项目的接点

- `/books`：作为升级入口
- `/topics`：作为专题浏览模式
- `书的世界`：作为单书关系视图
- `学习路径地图`：作为路径可视化容器

## 7. 验证方式

- 页面能加载
- 点位能显示
- 点击能命中
- 信息卡能打开
- 详情页能跳转
- 移动端不崩
