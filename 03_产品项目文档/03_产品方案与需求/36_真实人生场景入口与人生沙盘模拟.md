# 新增想法：真实人生场景入口与人生沙盘模拟

> 创建时间：2026-05-01  
> 最近更新：2026-05-01  
> 当前状态：v0.2 结构化收敛稿 / 需求候选  
> 关联来源：`01_sources/05_mythinking/真实人生场景入口：把理论系统接到现实世界.md`  
> 关联产品：`Problem Case`、`问题工作台`、`思想伙伴选配器`、`学习路径地图`、`选题中台`、`能力路径`

## 1. 本轮判断

用户这次的关键洞察是：**当前系统缺少前端的真实场景入口。**

之前系统更像一个“知识和方法后端”，擅长：

- 理论抽象
- 方法整理
- 视角归纳
- 卡片结构化

但还没有稳定承接“真实的人生处境”——也就是用户最常带来的那些起点：

- 升学与选校
- 考研与专业选择
- 求职与职业转型
- 人际关系
- 亲密关系
- 育儿
- 家庭协作

因此，这不是一个单独的新功能，而是一次**产品入口层的重定义**：

> 从“用户来问一个抽象问题”升级成“用户带着一个真实人生场景进来，系统帮助他看全景、做推演、识别模式”。

## 2. 产品定位

### 2.1 这是什么

一个“真实场景 -> 全景地图 -> 人生沙盘 -> 模式识别 -> 复盘成长”的入口系统。

```text
真实场景
-> 全景地图
-> 选择与筛选
-> 个人特点 / 资源 / 兴趣
-> 沙盘推演
-> 模式显现
-> 教练复盘
-> 意识成长
```

### 2.2 这不是什么

- 不是代替报考指导老师；
- 不是给出具体名校/专业的内幕答案；
- 不是单纯的信息检索器；
- 不是抽象概念堆砌页；
- 不是只等用户先提出一个很抽象的问题。

## 3. 目标用户

| 用户类型 | 典型场景 |
| --- | --- |
| 升学学生 | 想看学校、专业、路径、未来可能性 |
| 家长 | 想知道孩子能怎么选、怎么判断、怎么准备 |
| 考研 / 升学准备者 | 想知道方向、门槛、路径和能力要求 |
| 求职 / 转型者 | 想知道自己适合什么位置、怎么补能力 |
| 关系困扰者 | 想理解关系模式、边界和互动惯性 |
| 自我发展者 | 想看见自己的成长边际和反复模式 |

## 4. MVP 体验

### 4.1 核心流程

```text
进入一个真实场景入口
-> 系统展示全景地图
-> 用户按兴趣 / 能力 / 资源筛选
-> 查看场景可能路径和风险
-> 进入沙盘推演 / 模式识别
-> 得到理论视角、方法建议和最小行动
```

### 4.2 第一版必须有的能力

- 有明确的现实场景入口；
- 能承接一类真实处境，而不是只展示概念；
- 能输出全景地图或选择地图；
- 能把用户特点接入筛选；
- 能看到不同路径的差异；
- 能看到问题背后的模式与能力缺口；
- 能连接到书、理论、方法和行动。

### 4.3 第一版不做的事

- 不做具体报考决策代办；
- 不做“名师内幕”式的信息服务；
- 不做强算命式人生判定；
- 不做过度精细的职业测评替代；
- 不把系统变成纯答题器或纯咨询器。

## 5. 页面结构建议

### 5.1 场景首页

| 区域 | 内容 |
| --- | --- |
| 顶部 | 场景标题、入口说明、搜索 / 切换入口 |
| 中央 | 全景地图 / 选择地图 / 沙盘主视图 |
| 右侧 | 当前场景的说明、风险、建议、推荐入口 |
| 底部 | 场景切换、能力轴、复盘入口 |

### 5.2 场景内容卡

一个场景卡至少要包含：

- 场景名称
- 现实困境说明
- 选择维度
- 兴趣 / 能力 / 资源过滤项
- 风险提示
- 推荐书 / 方法 / 视角
- 最小行动

## 6. 数据模型建议

建议新增一层统一的场景对象：

```json
{
  "id": "exam-school-selection",
  "type": "life-scene",
  "title": "高考升学 / 选校",
  "summary": "在信息不对称中做未来路径选择",
  "ageStage": "pre-college",
  "sceneTags": ["升学", "选校", "未来规划"],
  "choiceDimensions": ["兴趣", "能力", "城市", "路径", "风险"],
  "knowledgeNeeds": ["全景地图", "筛选方法", "能力匹配"],
  "relatedBooks": ["..."],
  "relatedThinkers": ["..."],
  "relatedPaths": ["..."],
  "minimumAction": "列出 3 个最想比较的方向"
}
```

如果需要更贴近产品实现，可以再扩出：

- `sceneCases`：不同人生阶段的场景包；
- `choiceMap`：选择维度与筛选逻辑；
- `simulationSteps`：沙盘推演步骤；
- `reviewPrompts`：复盘提问模板。

## 7. 和现有产品的接法

### 7.1 接 Problem Case

Problem Case 是更细粒度的“问题卡”，而真实场景入口是更上游的“人生场景卡”。

两者关系可以理解为：

```text
人生场景入口
-> Problem Case
-> 书 / 视角 / 方法 / 行动
```

例如：

- 场景：高考升学
- Problem Case：我不知道怎么在大量信息里筛选出适合自己的学校
- 输出：全景地图、选择维度、能力匹配、行动建议

### 7.2 接思想伙伴选配器

思想伙伴不只是在“抽象问题”里工作，也可以在具体场景里工作：

- 帮用户看见不同视角；
- 帮用户理解筛选逻辑；
- 帮用户避免单一答案依赖；
- 帮用户看到自己可能忽略的维度。

### 7.3 接学习路径地图

当场景被理解后，系统要回到：

- 我缺的是什么能力？
- 我该学什么？
- 我该练什么？
- 我该输出什么？

### 7.4 接选题中台

真实场景本身就是内容母题来源：

- 升学焦虑
- 选校纠结
- 职业选择
- 关系误会
- 育儿冲突

这些都可以变成更有真实感的选题，而不是先讲概念。

### 7.5 接能力路径

能力路径不只是职业技能，也包括：

- 选择能力
- 判断能力
- 关系能力
- 自我理解能力
- 复盘能力

## 8. 这条母题的产品价值

这个方向会让产品从“知识仓库”升级成“现实入口系统”：

- 用户能从自己真实处境进入；
- 系统能给出全景而不是碎片；
- 理论不再悬浮，而是嵌回真实问题；
- 沙盘推演和复盘让人看见自己的模式；
- 产品价值从“信息”上升到“成长导航”。

## 9. 风险与边界

需要特别明确：

- 不做伪装成报考专家的服务；
- 不把具体名校/专业结论当成唯一正确答案；
- 不把沙盘推演做成玄学占卜；
- 不让系统变成只会给宏大 picture、却没有落点；
- 每个场景都必须能收束到一个可执行的小动作。

## 10. 优先级建议

### P1

- 把“真实场景入口”写进产品主叙事；
- 先做升学 / 选校样张；
- 把场景对象和 Problem Case 的关系写清楚；
- 让学习路径、思想伙伴、选题中台都能从场景入口反向接入。

### P2

- 扩展到考研、求职、关系、育儿等更多人生阶段；
- 增加更完整的人生沙盘推演流程；
- 形成可视化的“全景地图”与“模式地图”。

## 11. 结论

这个想法的本质不是一个功能点，而是产品入口层的升级：

> **从抽象问题驱动，升级为真实人生场景驱动。**

它会把现在已有的书、理论、方法、选题和能力路径，统一接到同一个现实世界入口上。

## 12. v0.2 MVP 切片

### 12.1 第一版只验证什么

第一版不急着做完整“人生模拟器”，先验证一个更小的问题：

> 用户是否愿意从一个真实人生场景进入系统，并沿着“全景地图 -> 问题卡 -> 学习/能力路径 -> 最小行动”的链路继续探索。

因此 v0.2 的 MVP 不是大平台，而是三类静态样张 + 一套统一场景对象：

| 切片 | 目标 | 产物 |
| --- | --- | --- |
| 场景入口 | 让用户从真实处境进入，而不是从抽象概念进入 | 场景卡、场景列表、场景首页结构 |
| 全景地图 | 让用户先看见维度、路径、风险和资源 | 每个场景 1 张全景地图样张 |
| 问题转译 | 把真实处境转成 Problem Case | 每个场景 3-5 个可进入的问题卡 |
| 沙盘推演 | 让用户看到不同选择可能带来的后果 | 轻量推演步骤，不做命运判断 |
| 最小行动 | 防止系统停在“看懂了” | 每个场景 1-3 个今天能做的小动作 |

### 12.2 第一版明确不做什么

为了避免和另一个 2.5D / 3D 页面任务冲突，当前文档只负责“场景产品层”和“数据结构层”：

- 不实现 2.5D / 3D 可视化；
- 不改 `3D地球书库` 相关文档或代码；
- 不引入新的空间浏览交互；
- 不接第三方实时学校、岗位或咨询数据；
- 不做个性化长期档案；
- 不生成强结论式人生建议。

如果后续要接入 2.5D / 3D，只把这里定义的 `LifeScene`、`SceneMap`、`SimulationStep` 作为数据输入，让视觉层自行决定怎么渲染。

## 13. 核心对象模型

### 13.1 LifeScene

`LifeScene` 是真实人生场景入口的主对象，负责承接“用户现在带着什么处境进来”。

```json
{
  "id": "career-transition",
  "type": "life-scene",
  "title": "求职 / 职业转型",
  "summary": "从岗位焦虑进入能力地图和转型判断",
  "stage": "adult-career",
  "userLanguage": [
    "我不知道自己适合什么岗位",
    "我想转型，但不知道下一步怎么走"
  ],
  "entryQuestions": [
    "我现在卡在什么选择上？",
    "我有哪些资源和限制？",
    "我最担心的风险是什么？"
  ],
  "sceneMapId": "career-transition-map",
  "problemCaseIds": ["career-fit", "career-switch-risk", "career-skill-gap"],
  "learningPathIds": ["career-skill-map"],
  "abilityAxisIds": ["judgement", "choice", "expression", "action"],
  "minimumActions": [
    "列出 3 个目标岗位",
    "对照 3 个关键能力缺口",
    "写出 1 个作品集或简历改进动作"
  ]
}
```

### 13.2 SceneMap

`SceneMap` 负责表达这个场景里的全景结构，不要求第一版做复杂图形，先用结构化块呈现。

| 字段 | 含义 |
| --- | --- |
| `dimensions` | 用户需要比较的维度，例如兴趣、能力、城市、风险、路径 |
| `options` | 这个场景下可比较的方向或选择分支 |
| `constraints` | 用户必须面对的限制，例如时间、成绩、履历、家庭资源 |
| `risks` | 常见误判和后果 |
| `evidenceNeeded` | 做判断前还缺什么信息 |
| `nextQuestions` | 可继续进入 Problem Case 的问题 |

### 13.3 SimulationStep

沙盘推演不做“预测命运”，只做“选择后果可视化”。

```json
{
  "id": "career-switch-path-a",
  "choice": "先保留当前工作，同时准备转型作品集",
  "shortTermEffect": "收入风险较低，但时间压力较高",
  "middleTermEffect": "可以用作品集验证方向，不必立刻跳槽",
  "hiddenCost": "如果没有固定节奏，容易一直拖延",
  "patternSignal": "回避不确定性，等待完美准备",
  "reviewPrompt": "这周你能交付哪一个可见的小作品？"
}
```

## 14. 用户流程细化

### 14.1 标准路径

```text
选择场景
-> 输入真实原话 / 当前状态
-> 查看全景地图
-> 选择 2-3 个想比较的维度
-> 生成 Problem Case
-> 进入思想伙伴 / 学习路径 / 能力路径
-> 输出最小行动
-> 记录反馈并复盘
```

### 14.2 低门槛路径

如果用户暂时不知道怎么描述，系统应该允许他先点选：

- 我在做选择；
- 我在担心风险；
- 我不知道自己适合什么；
- 我在关系里被一句话触发；
- 我想知道下一步怎么练。

点选后再补一句原话，而不是一开始就要求完整输入。

### 14.3 深度路径

当用户愿意多输入时，可以追加：

- 当前最在意的 3 个维度；
- 已有资源；
- 不可接受的风险；
- 过去重复出现的模式；
- 希望系统帮忙比较的选项。

深度路径的输出可以更接近“人生沙盘”，但仍然必须收束到最小行动。

## 15. 和现有模块的接口

| 目标模块 | 接入方式 | 第一版输出 |
| --- | --- | --- |
| Problem Case | 从 `LifeScene.problemCaseIds` 跳转 | 场景相关问题卡 |
| 思想伙伴选配器 | 根据场景和问题推荐视角 | 2-3 个最适合的思想伙伴镜头 |
| 学习路径地图 | 根据能力缺口推荐路径 | 1 条主路径 + 1 个最小练习 |
| 能力路径 | 把问题转成可发展能力 | 选择力、判断力、关系力、表达力等 |
| 选题中台 | 把真实场景转成内容母题 | 标题角度、情绪需求、内容结构 |

## 16. 验证指标

| 指标 | 说明 | v0.2 观察目标 |
| --- | --- | --- |
| 场景理解率 | 用户是否能在 10-20 秒内知道这个入口做什么 | 内部走查可清楚复述 |
| 继续探索率 | 用户是否愿意从场景进入 Problem Case 或学习路径 | 样张中入口明确可点击 |
| 最小行动清晰度 | 用户是否知道今天能做什么 | 每个场景至少 1 个具体动作 |
| 边界可信度 | 用户是否不会误以为系统替他做决定 | 页面明确表达“不代替决策” |
| 内容转译能力 | 场景能否反向变成选题或内容 brief | 每个样张至少给 3 个内容切口 |

## 18. 下一步建议

这组文档完成后，不建议立刻进入大开发。更稳的推进顺序是：

1. 先把 3 个样张当作静态页面原型走查；
2. 观察用户是否能从真实原话进入；
3. 再决定是否新增 `/tools/life-scenes` 入口；
4. 如果数据稳定，再把 `LifeScene` 写成配置文件；
5. 最后再考虑是否让 2.5D / 3D 页面读取这些场景对象，做空间化浏览。
