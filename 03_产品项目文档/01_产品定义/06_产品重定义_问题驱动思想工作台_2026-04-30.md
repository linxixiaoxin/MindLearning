# 产品重定义：从多书知识站到问题驱动思想工作台

> 创建时间：2026-04-30  
> 最近更新：2026-04-30  
> 当前状态：v0.2 产品定义输入  
> 来源思考：`01_sources/05_mythinking/0430.md`  
> 关联项目：`book-kb-multi` / 思想伙伴选配器 / 学习路径地图 / 50 本灰度扩容  

## 1. 本轮判断

`0430.md` 里的想法不应只停留在个人灵感文件里。它已经触发一次产品内核变化：

```text
book-kb-multi 不只是“多书知识站”，
而是要升级成“问题驱动的思想工作台”。
```

新的产品定义：

```text
一个帮助用户把真实生活困境转译成问题、视角、书籍证据、学习路径和行动输出的思想工作台。
```

原始灵感文件保留在 `01_sources/05_mythinking/0430.md`，用于追溯思考过程；本文件作为网站项目目录下的正式产品定义输入。

## 2. 网站内核变化

| 变化 | 旧内核 | 新内核 |
| --- | --- | --- |
| 主对象 | 书、章节、图谱、专题 | 真实问题 / 场景 / 情绪 / 能力目标 |
| 用户入口 | 用户先进来找书 | 用户带着困惑、情绪或事件进来 |
| 核心体验 | 展示整理好的知识资产 | 编排一段高质量思考过程 |
| 推荐结果 | 推荐书或专题 | 推荐角色、书籍证据、概念、学习路径和最小行动 |
| 行动重心 | 读完以后有收获 | 当下就能启动一个小动作 |
| 内容价值 | 内容资产库 | 问题 -> 知识 -> 输出 -> 反馈的生产闭环 |

最关键的变化是：网站不再只围绕 `book` 建模，而要新增一层更高阶的 `Problem Case`。

这个变化背后，还有一条更底层的统一母题：

```text
语言 -> 视角 -> 模式 -> 触发 -> 情绪 -> 需求 -> 表达 / 行动
```

它把当前项目里很多看似不同的模块连成了同一条链：

- 语言是思维框架和世界模型的外显。
- 视角决定同一件事会被看见成什么。
- 模式会被语言、场景和关系触发。
- 情绪是需要没有被看见时最早冒出来的信号。
- 内容、沟通、学习和产品，本质上都在做“从表层现象回到真正需要”的翻译。

这条母题已经分别落在几个地方：

- 思想伙伴选配器：从不同作者和学派给出多视角解释。
- 问题工作台：接住用户原话、情绪和 A / B / C 结构。
- 学习路径地图：把一个问题转成可学习、可练习、可输出的路径。
- 选题中台：把情绪翻译成需要，再翻成选题角度。
- 能力路径：按角色和能力组织练习、表达和行动。

更完整的整理见 `28_语言视角模式情绪需求统一母题.md`。

### 2.1 再往前一层：真实人生场景入口

用户后面又补出一个更上游的判断：`Problem Case` 之前，还应当有一层更贴近现实世界的 **真实人生场景入口**。

它负责接住的，不是抽象问题，而是更原始的人生处境：

- 高考升学 / 选校
- 考研 / 专业选择
- 求职 / 职业转型
- 人际关系 / 亲密关系
- 育儿 / 家庭协作

这层入口的任务是先给用户一个 **全景地图**，再让他进入问题工作台、思想伙伴、学习路径和能力路径。

也就是说，产品内核的上游可以进一步理解成：

```text
真实人生场景 -> Problem Case -> 知识 / 视角 / 方法 -> 学习 / 行动 / 复盘
```

这个补充不改变已有的 Problem Case 定义，而是让它前面多了一层现实世界入口。

## 3. 新核心对象：Problem Case

`Problem Case` 是连接用户问题、情绪、书籍、概念、思想伙伴、学习路径和行动输出的中间层。

第一版可用静态数据实现，不需要后端。

```js
{
  id: 'leader-communication-safety',
  title: '我总是怕和领导沟通，明明有想法也不敢说',
  entranceType: 'question',
  problemNaming: '这不是单纯表达问题，而是权力关系里的安全感问题',
  sceneTags: ['职场', '向上沟通', '表达边界'],
  emotionTags: ['恐惧', '紧张', '自我怀疑'],
  needTags: ['安全感', '被看见', '低风险表达'],
  recommendedThinkers: ['阿德勒', '非暴力沟通', '戈夫曼'],
  relatedBooks: ['非暴力沟通', '关键对话', '日常生活中的自我呈现'],
  relatedConcepts: ['观察-感受-需要-请求', '前台表演', '心理安全感'],
  learningPathId: 'difficult-conversation-safety',
  workshopModes: ['private-board', 'coach', 'torch-coach'],
  minimumAction: '写出 1 句事实 + 1 句影响 + 1 个请求'
}
```

建议第一阶段文件位置：

```text
web/src/data/problemCaseData.js
web/src/data/workshopModeData.js
```

中期再迁到：

```text
web/public/registry/problem_cases.json
```

## 4. 新产品体验

### 4.1 问题轻入口

目标：让用户不用先知道该读哪本书，也能从一个真实问题开始。

第一版入口：

| 入口 | 用户动作 | 输出 |
| --- | --- | --- |
| 抽一张问题卡 | 从预设问题中抽取或选择 | 进入对应 Problem Case |
| 情绪坐标 | 选择恐惧、迷茫、愤怒、痛苦等 | 显示情绪背后的需要和推荐路径 |
| 10 问量表 | 用轻量选项判断问题类型 | 推荐思想伙伴、学习路径和主书 |

建议路由：

```text
/tools/problem-lab
/tools/problem-lab/:caseId
```

### 4.2 问题工作台

问题工作台是新内核的主界面。它不是聊天页，而是结构化思考页。

页面模块：

| 模块 | 作用 | 可复用现有能力 |
| --- | --- | --- |
| 问题命名 | 把原始困惑改写成更准确的问题 | 思想伙伴规则、场景标签 |
| 情绪 / 需要坐标 | 说明当前情绪背后的可能需要 | 新增轻量数据表 |
| 多视角解释 | 展示 3-5 个思想伙伴或方法视角 | `thoughtPartnerData.js` |
| 书籍证据 | 展示主书、补充书、概念节点 | `books.json`、灰度池、公开 K/N |
| 学习路径 | 给出阶段化学习路线 | `LearningPathMap.vue` |
| 火把行动 | 给一个今天就能做的小动作 | `minimumAction` 字段 |
| 输出按钮 | 生成结构卡 / 小红书草稿 / 复盘卡 | 后续接内容输出流程 |

## 5. 多视角工作坊的产品形态

世界咖啡、私董会、教练技术、火把教练不应先做成四个大功能，而应作为同一个 `WorkshopMode` 的不同模板。

| 模式 | 第一版做法 | 优先级 |
| --- | --- | --- |
| 火把教练 | 固定模板 + 样张输出，照亮当前卡点和一个最小行动 | P0 |
| 教练技术 | 追问卡 + 行动承诺，把愿望推进到具体动作 | P0 |
| 私董会 | 角色追问 + 备选路径，适合真实决策问题 | P1 |
| 世界咖啡 | 多桌视角 + 共同母题，适合开放性问题 | P1 |

第一版不做实时 AI 对话。建议路线：

```text
预设问题样张
-> 固定模板输出
-> 人工审核文案
-> 收集用户点击和反馈
-> 再决定是否引入动态生成
```

## 6. 与现有站点模块的关系

不重做网站，而是在现有站上新增“问题层”。

| 现有模块 | 新角色 |
| --- | --- |
| `ThoughtPartnerTool.vue` | 成为问题工作台里的“多视角解释 / 思想伙伴”模块 |
| `LearningPathMap.vue` | 成为问题工作台里的“阶段化路线”模块 |
| `GrayBookPool.vue` | 作为问题案例的候选证据池，不直接公开原始 vault |
| `KnowledgeGraph.vue` | 用于证据关系图和概念关系图 |
| `ArticleReader.vue` | 打开已公开转写的 K/N 页和书内证据 |
| `BookLibrary.vue` | 仍保留为书籍入口，但不再是唯一主入口 |

`DEV-031` 仍然重要：补公开 K/N 页不是为了多几篇文章，而是为了让后续问题工作台有可信证据可以引用。

## 7. 第一批样张

第一版不超过 5 个 `Problem Case`。

| Problem Case | 已有基础 | 可验证什么 |
| --- | --- | --- |
| 为什么记了很多笔记，还是写不出来 | 已有学习路径 | 问题轻入口 + 学习路径 |
| 团队没人说真话，通常不是大家没想法 | 已有学习路径 | 私董会 / 世界咖啡视角 |
| 对方不讲道理时，先别急着摆事实 | 已有学习路径 | 情绪坐标 + 沟通行动 |
| 我总是靠直觉判断，事后才发现自己想简单了 | `思考，快与慢` / `模型思维` / `好好思考` | 连接认知决策书 |
| 我很难把真实需要说出口，一开口就变成指责 | `非暴力沟通` | 连接表达沟通书 |

## 9. 暂不做

| 暂不做 | 原因 |
| --- | --- |
| 完整 AI 自由聊天 | 容易让产品变成泛聊天机器人，证据和边界变弱 |
| 用户账号 / 历史保存 | 当前验证不依赖，工程成本高 |
| 视频链接自动解析 | 版权、平台兼容和技术复杂度较高，先支持文字稿 |
| 自由编辑画布 | 会稀释问题入口验证，先用 Mermaid / D3 解释结构 |
| 直接公开 50 本 vault | 与 public rewrite 分层原则冲突 |

## 10. 成功指标

| 指标 | 含义 |
| --- | --- |
| 问题入口点击率 | 用户是否愿意从问题而不是书名进入 |
| 结果页读完率 | 问题工作台是否过长、过散 |
| 学习路径跳转率 | 用户是否愿意继续看路径 |
| 主书点击率 | 推荐书是否有解释力 |
| 行动卡复制 / 点击率 | 网站是否真的促成最小启动 |

## 11. 当前结论

这次重定义不要求立刻中断 DEV-031。更稳的节奏是：

```text
DEV-031：先把 1 本书补成可引用的公开 K/N 证据
-> DEV-032：新增 Problem Case 数据层
-> DEV-033/034：做问题入口和问题工作台小样张
-> DEV-035：把火把教练 / 教练技术做成工作坊模板
```

也就是说，先继续把证据层补稳，再把问题层接上来。
